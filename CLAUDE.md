### Код и вёрстка
- **Без внешних UI-библиотек** — все страницы строятся без сторонних компонентных библиотек (без Bootstrap, MUI, Ant Design и подобных). Tailwind CSS — допустим, shadcn/ui — допустим, всё остальное — нет
- ⚠️ **Кнопки — только классами `.btn-gold` / `.btn-primary`** ([globals.css](web/src/app/globals.css)), НЕ своим `style={{background:'linear-gradient(...)'}}`. Золотая `.btn-gold` (`#FFCFA4`) — главное действие экрана, `.btn-primary` (тёмный градиент) — второстепенное. Копировать хардкод у соседней страницы нельзя: смысл единой точки настройки цветов в том и есть, что цвет меняется в CSS, а не в двадцати файлах. Так уже получилась страница с двумя тёмными плашками без фирменного акцента (2026-08-05).
- **Адаптивная вёрстка** — каждая страница должна хорошо выглядеть на мобильном экране. Проверять вёрстку на ширине 375px
- **Модалки НЕ закрываются по клику на затемнённый фон** (с 2026-06-26). Любая модалка-ФОРМА (с полями ввода/действиями) закрывается ТОЛЬКО по кнопке «Отмена»/крестику/«Закрыть» внутри окна — клик мимо окна НЕ закрывает (иначе теряются введённые данные). У внешнего div-оверлея НЕ вешать `onClick={onClose}`. Внутренний `onClick={e => e.stopPropagation()}` — оставлять. **Исключения** (там закрытие по фону норм и оставлено): лайтбоксы/просмотр картинок (ImagePreview, FileUploader, CollaboratorPostersField, posterLightbox, speaker setLightbox) и мобильное меню сайдбара (setMobileOpen).

### ⚠️ Фронт собирает GitHub, а НЕ прод (с 2026-08-21)

`npm run build` на проде больше не запускаем. Сборка шла **поверх работающей `.next`**: Next.js читал папку, которую в этот момент переписывали, — отсюда ошибки у клиентов и «сайт шатает 5–10 минут» при каждом деплое.

Теперь: пуш → GitHub собирает у себя → **сервер САМ приходит за готовой сборкой** по команде `deploygit` → [release.sh](deploy/release.sh) раскладывает её РЯДОМ со старой и переключает. Секунды вместо минут; не прошла проверка `/health` — автооткат на предыдущую версию.

⚠️⚠️ **GITHUB ПРО ПРОД НЕ ЗНАЕТ — и не должен узнать снова (с 2026-08-26).** Раньше GitHub заходил на сервер по SSH и раскладывал сборку сам. Значит любой, у кого есть право пушить в `main`, фактически дотягивался до прода: ключ и адрес лежали в секретах Actions, а скрипт деплоя выполняется на сервере **от root** — кто пушит, тот может выполнить на проде что угодно. Секреты `DEPLOY_HOST` / `DEPLOY_SSH_KEY` / `DEPLOY_USER` **удалены**, автозапуск выкатки по пушу убран, [deploy.yml](.github/workflows/deploy.yml) оставлен только как история.

**Три команды на сервере** (`/usr/local/bin/`, работают с телефона через Termius):

| Команда | Что делает |
|---|---|
| **`deploygit`** | ОСНОВНАЯ. Находит сборку **последнего коммита `main`**, качает готовый архив, отдаёт в `release.sh`. На проде ничего не собирает. Сборка идёт или ещё не началась — скажет подождать (`deploygit --wait` дождётся сам); упала — не выкатит вовсе. `deploygit --last` — осознанно взять последнюю успешную, даже если она не самого свежего коммита |
| `deploy` | Запасная: собирает кабинет и Mini App **прямо на проде** (2–5 минут, гасит Celery ради памяти). Только если GitHub недоступен |
| `status` | Что живо, что нет |

⚠️⚠️ **«Эта сборка уже на проде» считается по отметке `/var/www/plusson/.deployed_sha`, а НЕ по git HEAD** (26.08.2026). Раньше сверялись с HEAD рабочей копии — и команда молча пропускала накат, когда коммит сделан **прямо на сервере** (а это штатный порядок: правка → коммит и пуш с сервера → `deploygit`). В такой момент HEAD уже новый, а сборка в `web/.next` ещё старая: в логе успех, на сайте старое. Отметку пишет [release.sh](deploy/release.sh) ПОСЛЕ переключения и проверки `/health`; отметки нет — версия неизвестна, катим (лишний накат безвреден, пропущенный — нет). **Проверять факт выкатки — по содержимому `web/.next`, а не по словам команды.**

⚠️⚠️ **`deploygit` ждёт сборку ИМЕННО последнего коммита, а `release.sh` встаёт на коммит привезённой сборки** (26.08.2026, после двух подряд тихих осечек). Обе ошибки выглядели как успешный деплой:
1. Команда брала «последнюю **успешную**» сборку. Сразу после пуша прогона нового коммита в списке ещё нет — выкатывался предыдущий, в логе «Деплой завершён успешно», правки на сайте нет.
2. `release.sh` делал `git reset --hard origin/main`, а сборка приезжала своего коммита. Пока она собиралась (минуты), `main` уезжал вперёд — и на прод приезжали **сборка одного коммита и код другого**. Теперь встаём ровно на `NEW_SHA`; выкатка не самого свежего коммита печатает предупреждение вслух.

⚠️ **Список изменившегося считается от `.deployed_sha`, а не от git HEAD** — от него зависит, что рестартовать. По HEAD скрипт сравнивал не те коммиты и рестартовал не то.

⚠️ **`plusson-api` рестартуем на ЛЮБОЙ файл в `backend/app/`.** Прежнее перечисление папок (`api|services|main.py|…`) пропустило `backend/app/middleware/` — код приехал, процесс остался на старом, и разморозка оплаты подписки выкатилась нерабочей. Перечисление ошибается молча и в опасную сторону; лишний рестарт api стоит секунды.

⚠️⚠️ **`/usr/local/bin/deploygit` — СИМЛИНК на [deploy/deploygit](deploy/deploygit), не копия** (26.08.2026). Была отдельная копия файла: правки в репозитории до команды не доезжали вовсе, и починка деплоя «не работала», хотя код был верный. Из-за симлинка файл обязан оставаться исполняемым — бит `+x` зафиксирован в git (`git update-index --chmod=+x`), иначе команда отвечает `Permission denied`. ⚠️ Команда `deploy` (запасная, собирает на проде) до сих пор отдельная копия и разошлась с `deploy/deploy.sh` — при следующей правке привести к тому же виду.

⚠️ **Токен GitHub — в `/root/.github_token`** (в репозитории его нет), права **только на чтение**: скачать сборку можно, изменить или выкатить — нельзя. Без него `deploygit` не работает: у артефактов сборки нет публичного адреса.

⚠️ **Правка через `c` (Claude на сервере) обязана уходить в git.** `deploy` делает `git reset --hard` — незакоммиченная правка будет стёрта, и человек не поймёт, почему всё вернулось. Порядок: правка → коммит и пуш прямо с сервера → `deploygit`.

⚠️ **На сервер едет только `.next/server` + `.next/static` + четыре сборки mini-app.** `.next/cache` (350 МБ) серверу не нужен — это кеш сборки, отсюда 25 МБ вместо гигабайтов.

⚠️ **Рестартуем ТОЛЬКО то, чей код менялся.** Прежний `deploy.sh` рестартовал всё подряд каждый раз: правишь кнопку на лендинге — ложатся боты и обрывается Celery на середине рассылки.

## Дизайн-система

**Референс:** Slack.com — структура и навигация, но в бренд-цветах с градиентами
**Ощущение:** статусно, бизнесово, premium
**Тема:** светлая основа с тёмными акцентами

| Роль | HEX |
|---|---|
| Основной (фон, шапки) | `#25455D` — всегда через градиент к `#0a1520` под углом 45° |
| Акцентный / Золото (кнопки, CTA, линии, декор) | `#FFCFA4` — персиково-жёлтый с металлическим отливом |
| Базовый (фон карточек) | `#FFFFFF` |

> **Правило градиента:** везде где фон `#25455D` — применять `linear-gradient(45deg, #25455D, #0a1520)`. Чистый `#25455D` без градиента не использовать.

- Sidebar-навигация слева в Web-кабинете (как Slack)
- Градиент фонов: `#25455D` → `#0a1520`, угол 45°
- Золотые линии и декор — цвет `#FFCFA4`
- Шрифт: **Roboto** (Google Fonts)
- Mini App: те же цвета, мобильная адаптация
- Логотип белый (тёмный фон): `images/logo_no_ivision_wwhite.png`
- Логотип синий (светлый фон): `images/logo_no_ivision_blue.png`
