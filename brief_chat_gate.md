# Спецификация: «Гейт по подписке в чатах»

> **Контекст для нового клода:** эту фичу обсудила Марго (владелец PLUSSON и его первый клиент) в соседней сессии в репо `ivision-conf`. Спека написана там, сохранена здесь для реализации.

---

## 1. Что это и зачем

Новая фича в PLUSSON: владелец чата (клиент PLUSSON) может включить «гейт по подписке» в Telegram-чатах своих событий. Бот проверяет каждое входящее сообщение в чате: если автор не подписан на указанный канал — сообщение удаляется и (опционально) бот пишет «Чтобы писать в этот чат, подпишитесь на канал @xxx».

**Зачем:** Марго хочет монетизировать свой чат-комьюнити, заставив новых участников подписываться на её канал основателя. Сейчас это решается сторонними ботами (ControllerBot, SubGuardBot и пр.) — мы переносим функцию в PLUSSON, чтобы клиенты не плодили лишние боты в своих чатах.

---

## 2. Архитектурные решения (зафиксированы)

### 2.1. Где настройка в Admin
**Отдельный раздел в общих настройках клиента**, НЕ на странице события.

**Почему:** один и тот же Telegram-чат часто переиспользуется между событиями клиента. Если повесить настройку на событие, получится дублирование: одно событие включило гейт, другое нет, а чат-то один. Бот будет получать противоречивые инструкции.

### 2.2. Формат — список чатов
В разделе хранится **список** чатов с гейтом (не один). Клиент может включить гейт в нескольких своих чатах одновременно — каждый с собственными настройками.

### 2.3. Какой бот делает проверку
Та же логика, что в [backend/app/api/subscription_check.py:145-158](backend/app/api/subscription_check.py#L145-L158):

- **VIP-клиенты** → их собственный VIP-бот (через `get_client_telegram_token(client_id, db)`)
- **Обычные клиенты** → системный `@pluson_bot` (`settings.telegram_bot_token`)

Резолв токена при обработке сообщения — по `chat.id` → `client_chat_gates.client_id` → `channels.bot_token`.

### 2.4. Polling уже работает для всех ботов
`backend/bot/main.py:80-120` уже запускает polling и для дефолтного `@pluson_bot`, и для всех VIP-ботов клиентов в едином Dispatcher. Новый хэндлер на сообщения в группах **автоматически заработает для всех ботов** без доп. инфраструктуры.

### 2.5. Логика проверки подписки — переиспользовать
В [backend/app/api/subscription_check.py:51-67](backend/app/api/subscription_check.py#L51-L67) есть `_get_chat_member(token, channel_id, user_id)` — берём как есть. Возможно, вынести в отдельный сервис, если ещё не вынесен, чтобы импортировать из бота.

## 3. Структура БД

**Канал для проверки НЕ хранится в этой таблице** — берётся в рантайме из настроек основателя клиента (см. раздел 3.1).

Новая таблица:

```sql
CREATE TABLE client_chat_gates (
  id              BIGSERIAL PRIMARY KEY,
  client_id       BIGINT NOT NULL REFERENCES clients(id) ON DELETE CASCADE,
  chat_id         TEXT   NOT NULL,                       -- Telegram chat ID (числовой -100..., или @username)
  chat_title      TEXT,                                  -- для отображения в Admin
  warning_text    TEXT,                                  -- кастомный текст; NULL → дефолт (см. 3.2)
  warning_ttl_sec INT    NOT NULL DEFAULT 15,            -- авто-удаление предупреждения
  is_active       BOOLEAN NOT NULL DEFAULT TRUE,
  created_at      TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  updated_at      TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  UNIQUE (client_id, chat_id)
);

CREATE INDEX idx_client_chat_gates_chat_id ON client_chat_gates(chat_id) WHERE is_active;
```

Миграция: новый файл в `db/migrations/` следующего номера.

### 3.1. Откуда брать «канал основателя»

Из настроек клиента — раздел «Соцсети основателя → Telegram канал» (Admin: `/dashboard/settings`). У клиента уже хранятся:
- `Ссылка на канал` (https://t.me/+invite или https://t.me/public)
- `ID канала` (числовой `-100...`, нужен для `getChatMember`)
- Имя основателя (откуда-то из настроек клиента)

**Найди существующие колонки в `clients` или соответствующей таблице настроек и используй их.** Не дублируй.

Если канал в настройках клиента **не заполнен** — гейт не работает, в Admin UI показать ошибку «Сначала заполните Telegram-канал в настройках основателя».

### 3.2. Дефолтный текст предупреждения

```
Для того чтобы писать сообщения в чат, подпишитесь на канал основателя {founder_name}: {channel_url}
```

Плейсхолдеры:
- `{founder_name}` — имя основателя из настроек клиента
- `{channel_url}` — invite-link / public URL канала из настроек клиента
- `{user_name}` — `message.from_user.first_name`

Клиент может переопределить текст в UI (поле `warning_text`).

  - НЕ редактируется в модалке. Показывается как readonly-инфо: «Канал основателя: {founder_name} · {channel_url}» со ссылкой «Изменить в настройках основателя».

- **TTL предупреждения** (число секунд, дефолт 15) — через сколько секунд бот сам удалит предупреждение

## 7. Важное предупреждение пользователю

Для работы хэндлера на сообщения в группах **у бота должен быть отключён privacy mode**:

- В BotFather: `/mybots` → выбрать бот → Bot Settings → Group Privacy → **Disable**
- Без этого Telegram присылает боту только сообщения с упоминанием/reply, а нам нужны все

Это нужно подсветить в UI крупно — иначе пользователь будет жаловаться «бот ничего не удаляет».

## 8. Решения от Марго (зафиксировано)

1. **Каналы для проверки** — берутся из настроек основателя клиента (Admin → Настройки → Соцсети основателя → Telegram канал). В БД `client_chat_gates` НЕ дублируются. В UI модалки чата каналы показываются readonly со ссылкой «Изменить в настройках основателя».
2. **Чужие каналы запрещены.** Только каналы самого клиента-основателя. Партнёрство решается через добавление партнёрского канала в настройки основателя.
3. **Сценарий — только «удалить + предупреждение».** Опции «удалить молча» нет, поля `behavior` в таблице нет.
4. **Текст предупреждения по умолчанию:** `Для того чтобы писать сообщения в чат, подпишитесь на канал(ы) основателя {founder_name}: {channel_urls}`. Клиент может переопределить.
5. **MVP — только Telegram.** VK/MAX — в будущем.
6. **Несколько каналов основателя — поддержать в этом же спринте.** Вариант B: участник должен быть подписан на **ВСЕ** каналы клиента, иначе пишет нельзя. См. раздел 11.
7. **Видимость предупреждения:** сообщение видят все в чате (Telegram не умеет приватные сообщения в группах). Снижение раздражения — авто-удаление через 15 сек + отправка как **reply** на удалённое сообщение (визуально привязано к нарушителю).

## 11. Расширение: несколько Telegram-каналов в настройках основателя

**Скоуп этого спринта:** изменить раздел «Соцсети основателя → Telegram канал» в Admin с **одного** канала на **список** каналов, и подружить с гейтом по принципу «подписан на ВСЕ → пропускаем».

### 11.1. БД

Если сейчас канал хранится **одним полем** в таблице настроек клиента (что-то вроде `clients.tg_channel_url` + `clients.tg_channel_id`) — вынести в отдельную таблицу:

```sql
CREATE TABLE founder_tg_channels (
  id           BIGSERIAL PRIMARY KEY,
  client_id    BIGINT NOT NULL REFERENCES clients(id) ON DELETE CASCADE,
  channel_url  TEXT NOT NULL,                    -- https://t.me/... (invite или public)
  channel_id   TEXT NOT NULL,                    -- -100... для getChatMember
  display_name TEXT,                             -- название канала для UI/уведомлений
  sort_order   INT NOT NULL DEFAULT 0,
  is_active    BOOLEAN NOT NULL DEFAULT TRUE,
  created_at   TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  UNIQUE (client_id, channel_id)
);
```

**Миграция данных:** старые `clients.tg_channel_*` поля → одна строка в `founder_tg_channels` для каждого клиента, у кого они заполнены. Старые колонки потом удалить (отдельной миграцией после прохождения деплоя).

Если в текущей схеме поля называются иначе — найди их и адаптируй.

### 11.4. Логика гейта в чате (раздел 5 → расширенная версия)

```python
# Вместо одного getChatMember — параллельная проверка ВСЕХ активных каналов основателя:
channels = await db.fetch(
    "SELECT channel_id, channel_url, display_name FROM founder_tg_channels "
    "WHERE client_id = $1 AND is_active = TRUE",
    client_id
)
verdicts = await asyncio.gather(*[
    _get_chat_member(bot.token, ch["channel_id"], message.from_user.id)
    for ch in channels
])
not_subscribed = [ch for ch, (ok, status) in zip(channels, verdicts)
                  if not ok or status not in SUBSCRIBED_STATUSES]
if not not_subscribed:
    return  # подписан на все → пропускаем
# Иначе удалить + предупреждение со списком неподписанных каналов
```

### 11.5. Дефолтный текст предупреждения для нескольких каналов

```
Для того чтобы писать в чат, подпишитесь на канал(ы) основателя {founder_name}:
{channels_list}

где {channels_list} — каждая строка вида:
  • {display_name}: {channel_url}
```

Плейсхолдер `{channels_list}` рендерится только из тех каналов, на которые юзер ещё НЕ подписан (а не всех).

### 11.6. Обратная совместимость для проверки подписки в TMA

Существующий код `backend/app/api/subscription_check.py` сейчас проверяет подписку на каналы **спикеров** через `collaborators.tg_channel_id`. Эта логика остаётся как есть.

**Не путать:** каналы основателя ≠ каналы спикеров события. Гейт в чате использует только каналы основателя из `founder_tg_channels`. TMA-проверка для входа в чат через кнопку — каналы спикеров события.

Если у клиента сейчас канал основателя дублируется как «свой собственный канал спикера» (он же организатор события) — это уже отдельная история, не трогаем.
