# Инструкция: проброс GET-параметров со страницы лендинга в виджеты GetCourse

> Памятка для будущего Claude / разработчика. Здесь — все шаги, имена и грабли, на которые я наступила в этом проекте, когда настраивала автозаполнение скрытых полей формы GC из URL страницы.

---

## Контекст задачи

Лендинг [kreativ_chempionat.html](apps/tma/kreativ_chempionat.html) открывается с URL вида:

```
https://ivision.pluson.ru/kreativ-chempionat?pluson_contact_id=11624&pluson_participant_id=3191&tg_id=8018913774&email=tiny_daisy%40mail.ru&phone=79931354897&name=Маргарита&tg_nickname=forbs_margo2&event_slug=cygum
```

На лендинге 4 тарифа → 4 платёжных виджета GetCourse (каждый = свой iframe-форма). При клике «Оплатить» открывается модалка с виджетом. **Цель:** значения из URL автоматически попадают в поля формы виджета и сохраняются в карточке пользователя GC.

---

## Главное, что нужно понимать с самого начала

### 1. GC сам пробрасывает URL-параметры в iframe виджета
Проверено в DevTools → Network: при загрузке iframe виджета его src имеет вид:
```
https://medialift.margoforbs.ru/pl/lite/widget/widget?pluson_contact_id=11624&pluson_participant_id=3191&tg_id=...&id=1608251&ref=...&loc=...
```
То есть **все параметры со страницы уже доступны внутри iframe** через `window.location.search`. Дополнительно ничего пробрасывать не надо.

### 2. Но GC сам по себе НЕ заполняет ими поля формы
GC из URL подхватывает только:
- партнёрский id (через cookie, отдельный механизм трекинга)
- иногда utm-метки (через системные доп. поля `gc_system_user_utm_*`)

Все остальные параметры (включая стандартные `email`/`phone`/`name`) **сами по себе никуда не попадают**. Нужен JS внутри формы.

### 3. Решение — HTML-блок со скриптом внутри формы виджета
GC даёт возможность вставить произвольный `<script>` через блок «HTML». Скрипт работает внутри iframe формы, читает `window.location.search` и записывает значения в нужные input'ы.

---

## Чего делать НЕЛЬЗЯ (мои грабли)

### ❌ НЕ делай lazy-load виджета
Не пытайся убрать `<script src="...widget/script?id=NNNN">` из HTML страницы и инжектить его динамически при клике на кнопку. GC-скрипт виджета подписан на **`DOMContentLoaded`** — если он добавляется после загрузки страницы, событие уже не сработает, и **форма никогда не отрисуется** (модалка останется пустой). Виджет должен быть встроен сразу при загрузке страницы.

### ❌ НЕ добавляй параметры в URL скрипта виджета
Не делай так:
```html
<script src="...widget/script?id=1608251&tg_id=12345&..."></script>
```
GC **игнорирует** доп. параметры в URL своего скрипта. Он строит `iframe.src` строго из `window.location.search` страницы.

### ❌ НЕ ищи поля по `span:contains("имя_поля")`
В формах GC **нет span'а с подписью поля** — есть `<label>` и `<input id="field-input-{ID}">`. Селектор `span:contains("pluson_participant_id")` всегда вернёт пустой результат.

### ❌ НЕ оставляй у доп. поля видимость «Скрыть поле»
В админке GC у каждого доп. поля есть «Видимость поля». Если стоит **«Скрыть поле»** (внутри: `"hide":"2"`) — GC будет рендерить input в DOM формы, но **не сохранит значение в карточку**, даже если JS его заполнит. Правильный вариант — **«Показывать всегда» + CSS-класс `hide` на блоке поля в виджете** (см. Шаг 3).

### ❌ НЕ забывай, что виджеты изолированы
Один HTML-блок со скриптом, добавленный в виджет 1599504, **не влияет** на остальные виджеты (1599505, 1608251, 1599506). Скрипт нужно копировать в каждый виджет, где должен работать.

## Шаг 1. Найти числовые ID доп. полей в GC

GC использует **числовые внутренние ID** для адресации полей формы. Например `pluson_participant_id` в DOM это `<input id="field-input-13740683">`. Без этого ID невозможно написать рабочий селектор.

**Быстрый способ узнать ID сразу всех полей (1 минута):**

1. Открой `https://ВАШ_АККАУНТ.getcourse.ru/pl/logic/context/custom-fields?contextName=UserContext`
2. В Chrome нажми Cmd+U (View Source)
3. Найди в JS-конфиге участок `fields: [...]` — там массив всех доп. полей с `id` и `label`. Пример:
   ```json
   {"id":13740683,"label":"pluson_participant_id","type":"string",...,"hide":"2"}
   ```
4. Выпиши пары `URL-параметр → ID поля`.

**Для проекта iVision (аккаунт `ivision-medialift.getcourse.ru`):**

| URL-параметр (из ?...) | ID поля в GC | label в GC |
|---|---|---|
| `pluson_participant_id` | **13740683** | `pluson_participant_id` |
| `pluson_contact_id` | **13740684** | `pluson_contact_id` |
| `tg_id` | **11132047** | `tg_id` |
| `tg_nickname` | **11224895** | `tg_nickname` |
| `vk_id` | **13740682** | `vk_id` |
| `pluson_cid_answer` | 13740800 | `pluson_cid_answer` |
| `pluson_pecid_answer` | 13740801 | `pluson_pecid_answer` |

> `event_slug` пока в системе нет — если нужно сохранять, нужно создать поле руками: Пользователи → Доп. поля → Добавить поле, тип «Строка», заголовок `event_slug`.

## Шаг 2. Настроить видимость доп. поля в GC

Для каждого поля из таблицы:

1. GC → Пользователи → Доп. поля → клик по полю
2. Справа в панели «Видимость поля» → выбрать **«Показывать всегда»** (НЕ «Скрыть поле»)
3. Если поле должно использоваться для дедупликации пользователей (например `tg_id`) — оставить галку **«Является ключевым»**. Тогда повторная регистрация с тем же `tg_id` обновит существующего юзера, а не создаст дубль.
4. Сохранить.

> **Почему «Показывать всегда», а не «Скрыть поле»:** при «Скрыть» GC не сохраняет значение из формы в карточку. При «Показывать всегда» сохраняет — а визуально мы поле скроем через CSS-класс в Шаге 3.

## Шаг 3. Добавить поля в форму виджета + повесить класс `hide`

В этом проекте 4 виджета (по одному на тариф):

| Тариф | ID виджета | URL редактора |
|---|---|---|
| Тариф 1 «Этап 1 Чемпионата ЖИВУ» | **1599504** | `…/pl/lite/widget/editor?id=1599504` |
| Тариф 2 | **1599505** | `…/pl/lite/widget/editor?id=1599505` |
| Тариф 3 «Живой Спикер Чемпионата и Финала» | **1608251** | `…/pl/lite/widget/editor?id=1608251` |
| Тариф 4 «Онлайн + Вьетнам» | **1599506** | `…/pl/lite/widget/editor?id=1599506` |

В каждом виджете:

1. В редакторе виджета нажми на любое из существующих полей (например «E-Mail»). В нижнем меню появятся кнопки **«+ Поле пользователя»**, **«+ Предложение»**, и т.д. — это меню для добавления новых полей формы (НЕ путать с меню «Добавить блок» — то для контентных блоков).
2. Нажми **«+ Поле пользователя»** → в выпадающем списке выбери нужное доп. поле (например `pluson_participant_id`).
3. Когда поле добавлено в форму — кликни на его блок, открой «Style settings» → в поле **«CSS-класс блока»** впиши `hide` (или другое имя класса, который у вас скрывает блок через `display:none`).
4. Повтори для всех нужных полей: `tg_id`, `tg_nickname`, `pluson_participant_id`, `pluson_contact_id`, `vk_id` — кому что нужно.

> CSS-класс `hide` у нас уже определён в стилях виджета — он скрывает блок визуально через `display:none`, но input остаётся в DOM. Класс может называться и `hidden`, и любым другим — главное, чтобы он применял `display:none`.

## Шаг 4. Вставить HTML-блок со скриптом

В том же редакторе виджета:

1. Нажми **«+ HTML»** (меню «Добавить блок» — тоже доступно при клике на любое поле/блок формы).
2. Внутри HTML-блока вставь скрипт (см. финальный код ниже).
3. Поставь блок в самом низу формы — после кнопки «Зарегистрироваться» и после всех скрытых полей. Это нормально: с точки зрения DOM весь виджет — одна `<form>`, скрипт через `$(document).ready` запустится после полной загрузки DOM.
4. Сохрани виджет.

## Финальный JS-скрипт для HTML-блока

```html
<script>
$(document).ready(function(){
    // === Доп. поля пользователя — адресуем по ID input'а ===
    var CUSTOM = {
        'pluson_participant_id': 13740683,
        'pluson_contact_id':     13740684,
        'tg_id':                 11132047,
        'tg_nickname':           11224895
        // 'vk_id':              13740682,  // раскомментировать если нужен
    };
    Object.keys(CUSTOM).forEach(function(urlParam){
        var v = getQueryParam(urlParam);
        if (v !== false) {
            $('#field-input-' + CUSTOM[urlParam]).val(v).trigger('change');
        }
    });

    // === Стандартные поля — адресуем по атрибуту name ===
    var STD = {
        'email': 'formParams[email]',
        'name':  'formParams[full_name]',   // ВАЖНО: в URL "name", в форме "full_name"
        'phone': 'formParams[phone]'
    };
    Object.keys(STD).forEach(function(urlParam){
        var v = getQueryParam(urlParam);
        if (v !== false) {
            // Телефон в GC хочет международный формат → добавим +, если его нет
            if (urlParam === 'phone' && v.charAt(0) !== '+') {
                v = '+' + v;
            }
            $('input[name="' + STD[urlParam] + '"]').val(v).trigger('change');
        }
    });
});

function getQueryParam(name) {
    var m = window.location.search.match(new RegExp('[?&]' + name + '=([^&]+)'));
    return m ? decodeURIComponent(m[1]) : false;
}
</script>
```

**Замечания:**

- `jQuery` доступен в виджетах GC по умолчанию — отдельно подключать не нужно.
- `.trigger('change')` — нужен, чтобы GC «увидел» изменение значения программно (без него ряд интеграций может не подхватить).
- Селектор `[?&]name=...` важен — без префикса `[?&]` regex может ложно найти `id` внутри `participant_id`.
- Если в URL телефон уже с `+` или `%2B` (закодированный плюс) — скрипт не задублирует `+`.

## Шаг 5. Тестирование

1. Открой страницу лендинга с тестовым URL:
   ```
   https://ivision.pluson.ru/kreativ-chempionat?pluson_contact_id=11624&pluson_participant_id=3191&tg_id=8018913774&email=tiny_daisy%40mail.ru&phone=79931354897&name=Маргарита&tg_nickname=forbs_margo2
   ```
2. Нажми «Оплатить» в нужном тарифе → откроется модалка с iframe виджета.
3. Открой DevTools → Elements → войди в iframe → найди input `#field-input-13740683` → убедись, что `value="3191"`.
4. Сделай тестовую регистрацию.
5. В GC: Пользователи → найди созданного юзера → проверь, что все доп. поля заполнились.

**Если в DevTools value уже стоит, а в карточке поле пустое** — значит у поля в GC всё ещё стоит «Скрыть поле». Возвращаемся к Шагу 2 и ставим «Показывать всегда».

**Если value не появилось в input** — скрипт не нашёл поле. Проверь:
- Открыт ли HTML-блок в редакторе формы (а не где-то ещё)
- Правильный ли числовой ID в массиве `CUSTOM` (сверь с Шагом 1)
- Включена ли видимость поля «Показывать всегда»

## TL;DR

1. **Найди ID полей** в исходнике страницы `/pl/logic/context/custom-fields` (массив `fields`).
2. **Видимость поля = «Показывать всегда»** (НЕ «Скрыть поле») для каждого поля, которое надо заполнять из URL.
3. **В каждой форме виджета:** добавь нужные поля + CSS-класс `hide` на блок (визуальное скрытие).
4. **В каждой форме виджета:** вставь блок «+ HTML» со скриптом выше. Скрипт читает `window.location.search` и пишет значения в input'ы по ID и по name.
5. **Тестируй.** Если value стоит, но карточка пустая — значит видимость всё ещё «Скрыть поле».
