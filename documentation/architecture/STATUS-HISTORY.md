### ⚠️⚠️ Запрос прав ВКонтакте в Mini App: два разных сценария (2026-09-06, ПРОД)

Модерация ВКонтакте снимала приложение **дважды**, и оба раза — за то, КАК просятся права:
- **18.06.2026** — окна прав выскакивали молча, без объяснения (нарушение п.1.1.2 правил Mini Apps: предупредить ЗАРАНЕЕ, зачем право);
- **01.09.2026** — «сервис запрашивает подписку на сообщество **до просмотра его функций**»: окно `VKWebAppJoinGroup` показывалось сразу при открытии.

Отсюда два сценария, и путать их нельзя:

| Вход | Что видит человек | Подписка на сообщество |
|---|---|---|
| **Голый вход** (открыл приложение) | календарь → через 5 с наше окно-объяснение → системное окно «разрешить сообщения» | **НЕТ** |
| **По ссылке** события/лид-магнита | событие/заглушка → системное окно «разрешить сообщения» → окно «подписаться на сообщество» | **ДА** |

**Голый вход — путь модератора.** Там окно-объяснение обязательно (п.1.1.2), а подписки быть не должно — это и есть причина снятия 01.09.2026.

⚠️⚠️ **Подписка на входах ПО ССЫЛКЕ — осознанное решение владельца (05.09.2026), принятое после прямого предупреждения о риске:** модератор может открыть такую ссылку (они лежат в постах сообщества и рассылках). Причина решения — без автозапроса подписчики почти не приходят: 169 из 184 пришли через него, август дал 2, сентябрь — 0.

#### ⚠️ Различать входы — ТОЛЬКО по содержимому ссылки

⚠️⚠️ **При ГОЛОМ входе ВКонтакте присылает `startParam = "other"`, а НЕ пустую строку** (проверено диагностикой на проде 06.09.2026). Любая проверка «`startParam` непустой → пришёл по ссылке» считает голый вход ссылкой. Ровно на этом за 05–06.09.2026 сломалось несколько попыток подряд: чинишь ссылку — пропадает окно на голом входе, и наоборот.

Правильный признак — **содержимое**: часть `pg{slug}` (`parseStartParam`) либо префиксы `m_`/`p_`/`evl_`/`fnl_`/`spkinv_`/`prt`. Плюс адрес страницы `/vk/event/{slug}` — для перехода к событию уже внутри приложения.

#### ⚠️ Порядок вызова окон — подписка ВНУТРИ колбэка разрешения

```
adapter.requestWriteAccess({vkGroupId}, () => {   // окно 1
  adapter.joinGroup({vkGroupId}, () => {})        // окно 2 — отсюда и только отсюда
})
```

⚠️ **ВКонтакте показывает строго ОДНО системное окно за раз** и молча отбрасывает второе, если первое ещё открыто. Колбэк `requestWriteAccess` — единственный надёжный момент «первое окно закрыто».

Что проверено 05.09.2026 и **НЕ работает** (не повторять):
- подписка после колбэка или по таймеру (500 мс, 6 с, 12 с, 15 с) — второе окно теряется;
- ожидание ответа с таймаутом — колбэк приходит не всегда;
- подписка ПЕРВОЙ, разрешение из её колбэка — колбэк `joinGroup` не приходит вовсе (диагностика: `joinGroup:sent` есть, ответа нет);
- вечная отметка «права уже просили» (`__vkPermsAsked`) — гасила запрос насовсем;
- две независимые точки запроса — гасят друг друга.

#### ⚠️ Событие с режимом «лендинг» уводит webview — права просить ДО редиректа

У события бывает `registration_mode='landing'`: приложение перебрасывает человека на страницу регистрации, Mini App при этом закрывается — показывать окна становится некому. Поэтому запрос стоит в [EventPage.tsx](mini-app/src/pages/EventPage.tsx) **перед** `redirectToExternalLanding`, и редирект **ждёт** ответа.

⚠️ Страховка **8 секунд**, не больше: с 45 человек висел на странице события почти минуту, если ВК не отвечал.

#### ⚠️ «Разрешал ли уже» — спрашиваем у ВКонтакте, не у себя

Окно-объяснение не показывается тем, у кого право уже есть. Проверка — `GET /api/v1/vk/messages-allowed` ([vk_event.py](backend/app/api/vk_event.py)), которая ходит в **`messages.isMessagesFromGroupAllowed`** и только при неудаче смотрит нашу базу.

⚠️ **Прежнее «у VK Bridge такого метода нет» неверно** — метод есть и работает с токеном сообщества. Раньше показ решался записью в `platform_user_channels`, а она расходится с реальностью в обе стороны (`message_deny` ВК доставляет ненадёжно).

⚠️ **Отметка «уже показывали» живёт в браузере (`sessionStorage`), а не в базе** — из-за неё окно однажды пропало навсегда, когда была на `localStorage`.

#### ⚠️ Флаг «разрешил писать» в базе ставит ТОЛЬКО `message_allow`

`platform_user_channels.is_unsubscribed` — это **база рассылки**, а не «показывать ли окно». Ставит его ровно одно событие — `message_allow` (снимает `message_deny`), как `my_chat_member` в Telegram.

⚠️ Убраны четыре места, где он выставлялся неправомерно: `handle_group_join` (вступление в сообщество — **другое право**), `run_started_vk`, `run_started_partner_vk` (заход по ссылке разрешением не является). Ветка MAX оставлена: там человек попадает в воронку, только запустив бота.

⚠️ Подписаны события **`group_join` и `group_leave`** — обработчик вступления был написан давно, а событие у ВК не запрашивалось вовсе, и вступления до нас не доходили. `group_leave` право писать НЕ снимает: выход со стены и запрет сообщений — разные права.

### Mini App — единый пакет TG/VK/MAX (рефакторинг 2026-05-20)

С 2026-05-20 `mini-app/` обслуживает **все платформы** одним исходным кодом. Папка `mini-app-vk/` удалена. Структура:

```
mini-app/
├── src/
│   ├── platform/
│   │   ├── index.ts        — PlatformAdapter interface + getPlatform()/setPlatform()
│   │   ├── telegram.ts     — TG-адаптер (Telegram.WebApp)
│   │   ├── vk.ts           — VK-адаптер (@vkontakte/vk-bridge)
│   │   └── max.ts          — MAX-адаптер (window.WebApp, SDK подключается тегом)
│   ├── main-tg.tsx         — точка входа TG: init + setPlatform + рендер App
│   ├── main-vk.tsx         — точка входа VK
│   ├── App.tsx             — общий, branching через `platform.name`
│   ├── api.ts              — общий, getPlatformName() для ?platform= в нужных запросах
│   ├── tabs/ pages/ components/ — общие, физически по одному файлу
│   └── styles/
├── index_tg.html           — с inline-скриптом landing-redirect для TG
├── index_vk.html           — короче, без landing-redirect (VK работает иначе)
├── vite.config.tg.ts       — base: '/tg/', outDir: 'dist'
├── vite.config.vk.ts       — base: '/vk/', outDir: 'dist-vk'
└── package.json            — build:tg + build:vk + build (запускает оба)
```

**Сборка:**
```bash
cd mini-app && npm run build
# → dist/index.html + dist/assets/... (TG)
# → dist-vk/index.html + dist-vk/assets/... (VK)
```

**Правило:** любая фича в Mini App пишется один раз в `mini-app/src/` — попадает во все платформы автоматически. Платформо-специфичное (init SDK, обработка funnel-ссылок VK, диалоги VK Bridge на email/phone) — внутри `if (getPlatformName() === 'vk')` в App.tsx или в `platform/vk.ts`.

**MAX-фронт задеплоен (2026-07-28).** `main-max.tsx` + `index_max.html` (подключает `https://st.max.ru/js/max-web-app.js`) + `vite.config.max.ts` (base `/max/`, outDir `dist-max`) + nginx-блок `/max/` → `dist-max/`. Сборка — `npm run build:max` (входит в общий `npm run build`).

⚠️ **В настройках бота MAX (business.max.ru → Чат-боты → Расширенные настройки → Мини-приложение) указывается адрес С НОМЕРОМ КЛИЕНТА:** `https://pluson.ru/c/{client_id}/max/` (напр. `/c/1/max/` — кабинет Марго). Ровно как у Telegram (`/c/{N}/tg/`): nginx делает internal rewrite `^/c/\d+/(.*)$ → /$1` (правило `location ~ ^/c/\d+/(tg|vk|max)`), поэтому одна сборка обслуживает ботов всех клиентов, а приложение узнаёт клиента из пути. Адрес БЕЗ `/c/{N}/` (просто `pluson.ru/max/`) откроет приложение без контекста клиента — в бота его вписывать нельзя.

### Роутинг мини-апп и startapp-параметры

**Поток открытия:**
1. Пользователь открывает бота (по диплинку или напрямую)
2. `App.tsx` читает `twa.initDataUnsafe.start_param` — там может быть `ref_pid{id}_src{utm}`
3. Парсит `pid` → `partnerId`, `src` → `utmSource` — однозначно, без путаницы
4. Открывает `Dashboard`, который запрашивает события участника из БД по `telegram_id`
5. Если **1 событие** → авто-открывает `EventPage` для него
6. Если **несколько** → показывает список (участник выбирает)
7. Если **0 событий** → показывает экран «нет событий»

**Формат startapp:** `ref_pid{partner_id}_src{utm_source}`
- `ref` — обязательный префикс-маркер
- `pid` — реф-код партнёра (URL-параметр `?pid=…`, старое имя `?new_partner_id=…` поддержано как fallback), опционально
- `src` — utm_source, опционально
- Примеры: `ref`, `ref_pid5725111966`, `ref_srcinsta`, `ref_pid5725111966_srcinsta`

**Ссылки из лендинга (ivision-conf):**
- Веб: `https://ivision.pluson.ru/ivision-conf-7` (без `app=tg`)
- Бот: `https://ivision.pluson.ru/ivision-conf-7?app=tg[&pid=...][&utm_source=...]` (старое имя `new_partner_id` поддержано)
- Старый домен `https://ivision.margoforbs.ru/*` отдаёт 301-редирект на `ivision.pluson.ru/*` (на Beget nginx) — старые ссылки в Salebot/GetCourse/афишах продолжают работать, но новые публиковать только с новым доменом.
- Каждый HTML-лендинг содержит скрипт: если `app=tg` → redirect на `t.me/Margo_forbs_bot/ivision?startapp=...`

**partnerId / utmSource** передаются в `EventPage` для fallback-регистрации (если участник не был зарегистрирован через GetCourse).
