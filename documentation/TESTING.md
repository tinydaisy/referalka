# TESTING.md — Сценарии тестирования ПЛЮСОН

> Этот файл описывает что и как проверять перед деплоем и после изменений.
> Тесты делятся на: ручные сценарии (end-to-end) и проверки по компонентам.

## Приоритет тестирования

**Критично (без этого продукт не работает):**
1. Реферальная цепочка: клик → конверсия → начисление баллов → выдача подарка
2. Регистрация участника через бота
3. Mini App открывается и показывает правильный прогресс

**Важно (ключевые функции):**
4. Клиент создаёт событие и получает ссылку
5. Webhook от GetCourse засчитывает конверсию
6. Рассылка участникам уходит в правильный сегмент

**Дополнительно:**
7. Панель администратора показывает актуальные данные
8. Модуль «Конференция» отображает программу и спикеров

## Известные ограничения (не баги)

- Mini App не работает в обычном браузере — только внутри Telegram
- Проверка подписки на канал работает только если бот является администратором канала
- `points_scope = 'client'` (накопительные баллы across событий) — не реализован в MVP
- **E2E-тест воронки на dev требует отдельного TELEGRAM_BOT_TOKEN от прод-сервера.** Сейчас prod и dev используют один токен @pluson_bot → конфликт getUpdates при одновременном polling. Решение: завести второго бота через @BotFather и положить его токен в dev `.env`, либо тестировать воронку только на prod после деплоя.

## Свой домен клиента (миграция 270)

Раздел: Настройки → «Свой домен». Виден только на тарифе с фичей `custom_domain` (Экстра).

### Домен для страниц

1. Добавить домен → статус «Ждём DNS», показана запись CNAME.
2. Нажать «Проверить DNS» до настройки записи → отказ с понятным текстом, кнопка «Выпустить сертификат» остаётся заблокированной.
3. Добавить у регистратора `CNAME домен → pluson.ru`, подождать, снова «Проверить DNS» → «DNS настроен верно», кнопка выпуска разблокирована.
4. «Выпустить сертификат» → статус «Работает», видна дата окончания и остаток дней.
5. Открыть на своём домене: лендинг события `/e/{slug}`, кабинет спикера `/speaker/{slug}`, турнирную таблицу `/t/{slug}/{stage}`, воронку подарка `/m/{slug}`.
6. Открыть на своём домене `/dashboard` → должен увести на `pluson.ru/dashboard` (кабинет живёт только там).
7. Проверить, что ссылки в рассылке ведут на свой домен: сформировать рассылку и посмотреть превью.
8. Отключить домен → страницы на нём перестают открываться, всё возвращается на `pluson.ru`.

⚠️ Сертификат должен быть RSA. Проверка: `echo | openssl s_client -connect ДОМЕН:443 -servername ДОМЕН -showcerts 2>/dev/null | grep 'i:' | tail -1` → должен быть `ISRG Root X1`, НЕ `X2`.

### Домен для почты

1. Добавить домен → показаны три записи (SPF, DKIM, DMARC) с кнопками копирования.
2. «Проверить DNS» до настройки → видно, какая из трёх записей не встала.
3. Добавить записи в DNS, снова проверить → статус «Работает».
4. Отправить тестовую рассылку по email → письмо приходит с адреса `noreply@домен-клиента`, ссылка отписки ведёт на его же домен.
5. Проверить доставляемость через mail-tester.com — SPF/DKIM/DMARC должны быть PASS.

⚠️ Если SPF-запись на домене уже есть — вторую добавлять нельзя, нужно дописать `include:pluson.ru` в существующую. Две записи SPF ломают проверку.

### Обратная совместимость (проверять всегда)

У клиента БЕЗ своего домена всё должно работать ровно как раньше: ссылки в рассылках, боте, письмах и Mini App ведут на `pluson.ru`.

## Гейт платных модулей (миграция 276)

1. У клиента без модуля «Конференции» открыть карточку конференции → событие **находится и открывается**, вверху янтарная плашка «Модуль не подключён».
2. Доступны вкладки **Участники / Отчёт по привлечению / Заказы**; Программа, Спикеры, Оценки — с замком и не открываются.
3. Попробовать сохранить что-либо в закрытой вкладке → бэкенд отвечает 403, данные не меняются.
4. Спикерская рассылка на выключенном модуле **не уходит**, в очереди у неё видна причина.

7. Публичные страницы (лендинг события, программа, карточка спикера) работают **и без модуля** — участник не должен пострадать.

⚠️ Проверять обязательно на клиенте, у которого модуля НЕТ: на своём кабинете с полным доступом гейт не виден.

## Эквайринг Т-Банка (миграция 277)

1. Настройки → «Платёжные системы» → выбрать «Эквайринг Т-Банка», вписать Terminal Key и пароль → «Проверить связь» → «Связь есть».
2. Включить галочку «Работать на тестовом терминале», вписать тестовые ключи → проверка идёт уже по ним, вверху предупреждение про тестовый режим.
3. Оформить заказ платного тарифа на лендинге → открывается страница оплаты Т-Банка, сумма совпадает с ценой тарифа **до копейки**.
4. Оплатить тестовой картой → заказ становится «оплачен», участник зарегистрирован, письмо об оплате ушло.
5. Снять галочку теста → новые заказы уходят на боевой терминал; оплата по заказу, созданному до переключения, **всё равно засчитывается**.
6. Если у клиента подключён сервис «Чеки от Т-Бизнеса» — покупателю приходит чек (выдаёт сам банк, не мы).

⚠️ **Проверять гейт по ПРЯМОЙ ССЫЛКЕ, а не только по меню.** Замок в сайдбаре не мешает открыть `/dashboard/conferences`, `/dashboard/tournaments` и `/dashboard/conferences/new` напрямую. Без модуля на всех трёх должен быть замок с предложением подключить, а кнопок «Создать конференцию/турнир» быть не должно — ни в шапке, ни на пустом экране.
