# TESTING.md — Сценарии тестирования ПЛЮСОН

> Этот файл описывает что и как проверять перед деплоем и после изменений.
> Тесты делятся на: ручные сценарии (end-to-end) и проверки по компонентам.

---

## Приоритет тестирования

**Критично (без этого продукт не работает):**
1. Реферальная цепочка: клик → конверсия → начисление баллов → выдача подарка
2. Регистрация участника через бота
3. Mini App открывается и показывает правильный прогресс

**Важно (ключевые функции):**
4. Клиент создаёт событие и получает ссылку
5. Webhook от GetCourse засчитывает конверсию
6. Рассылка участникам уходит в правильный сегмент

**Дополнительно:**
7. Панель администратора показывает актуальные данные
8. Модуль «Конференция» отображает программу и спикеров

## Сценарий 12 — Тестовое письмо приходит с картинкой (2026-08-14)

Проверять после ЛЮБОЙ правки отправки писем: тест и боевая рассылка обязаны
выглядеть одинаково, иначе клиент проверяет вёрстку, которой в реальной
рассылке нет.

- [ ] Рассылка с фото → «Тест» → в Telegram картинка **и** в письме картинка (не пустое место, не ссылка)
- [ ] Картинка показана **в теле письма**, а не «прикреплением снизу» (Gmail на телефоне — самый строгий: тяжелее ~100 КБ уезжает вниз, поэтому JPEG сжимается до ~90 КБ)
- [ ] Кнопка рассылки есть и в письме (персиковая `#FFCFA4`), не только в боте
- [ ] Рассылка с видео → в письме кликабельная обложка со ссылкой (встроенного плеера в почте не бывает)
- [ ] Заголовок не задвоился: он в теме письма, а не ещё и первой строкой тела
- [ ] То же самое проверить в ОБОИХ разделах — событийные рассылки и общие `/dashboard/broadcasts` (точка теста общая, но проверять обе)

Быстрая проверка доставки на проде: `grep '<message-id>' /var/log/mail.log` → должно быть `status=sent (250 ... OK)`; размер письма в строке `qmgr` показывает, вложена ли картинка (с фото — сотни КБ, без — единицы КБ).

## Известные ограничения (не баги)

- Mini App не работает в обычном браузере — только внутри Telegram
- Проверка подписки на канал работает только если бот является администратором канала
- `points_scope = 'client'` (накопительные баллы across событий) — не реализован в MVP
- **E2E-тест воронки на dev требует отдельного TELEGRAM_BOT_TOKEN от прод-сервера.** Сейчас prod и dev используют один токен @pluson_bot → конфликт getUpdates при одновременном polling. Решение: завести второго бота через @BotFather и положить его токен в dev `.env`, либо тестировать воронку только на prod после деплоя.

## Свой домен клиента (миграция 270)

Раздел: Настройки → «Свой домен». Виден только на тарифе с фичей `custom_domain` (Экстра).

### Домен для страниц

1. Добавить **корневой** домен (`example.ru`) → статус «Ждём DNS», показана запись **A** `@` → `194.156.119.17` (НЕ CNAME — на корне он запрещён стандартом DNS).
2. Добавить **поддомен** (`lp.example.ru`) → показана запись **CNAME** → `pluson.ru`.
3. Домен с чужими записями (свежекупленный обычно висит на парковке регистратора) → кабинет первым шагом перечисляет найденные записи «удалите вот эти». Без их удаления новая запись не сработает.
4. Нажать «Проверить DNS» до настройки записи → отказ с понятным текстом (для корня зовёт ставить A-запись, для поддомена — CNAME), кнопка «Выпустить сертификат» остаётся заблокированной.
5. Прописать запись у регистратора, подождать, снова «Проверить DNS» → «DNS настроен верно», кнопка выпуска разблокирована.
6. «Выпустить сертификат» → статус «Работает», видна дата окончания и остаток дней.
7. Открыть на своём домене: лендинг события `/e/{slug}`, кабинет спикера `/speaker/{slug}`, турнирную таблицу `/t/{slug}/{stage}`, воронку подарка `/m/{slug}`.
8. Открыть на своём домене `/dashboard` → должен увести на `pluson.ru/dashboard` (кабинет живёт только там).
9. Проверить, что ссылки в рассылке ведут на свой домен: сформировать рассылку и посмотреть превью.
10. Отключить домен → страницы на нём перестают открываться, всё возвращается на `pluson.ru`.

⚠️ Сертификат должен быть RSA. Проверка: `echo | openssl s_client -connect ДОМЕН:443 -servername ДОМЕН -showcerts 2>/dev/null | grep 'i:' | tail -1` → должен быть `ISRG Root X1`, НЕ `X2`.

### Домен для почты

1. Добавить домен → показаны три записи (SPF, DKIM, DMARC) с кнопками копирования.
2. «Проверить DNS» до настройки → видно, какая из трёх записей не встала.
3. Добавить записи в DNS, снова проверить → статус «Работает».
4. Отправить тестовую рассылку по email → письмо приходит с адреса `noreply@домен-клиента`, ссылка отписки ведёт на его же домен.
5. Проверить доставляемость через mail-tester.com — SPF/DKIM/DMARC должны быть PASS.

⚠️ Если SPF-запись на домене уже есть — вторую добавлять нельзя, нужно дописать `include:pluson.ru` в существующую. Две записи SPF ломают проверку.

### Обратная совместимость (проверять всегда)

У клиента БЕЗ своего домена всё должно работать ровно как раньше: ссылки в рассылках, боте, письмах и Mini App ведут на `pluson.ru`.

## Бонус ПЛЮСОНа за оплату тарифа (миграции 307-311)

**Настройка**
1. Карточка события → «Тарифы» → правка тарифа → блок «Доступ в ПЛЮСОН за покупку».
2. Галочка «Дарить доступ в iViSiON: ПЛЮСОН» должна быть видна **у любого клиента**, даже без платных модулей.
3. Селектор модуля и «вместе с модулем дарим Профи» — только у admin.
4. Срок задаётся **в днях** (не месяцах).

**Строка на лендинге**
5. С галочкой «Писать бонус автоматически» — в карточке тарифа на `/e/{slug}` появляется «Бонус: …» с ОБОИМИ случаями («для новых» / «для действующих»).
6. Снять галочку → строка исчезает, остаётся только описание тарифа.
7. У тарифов без бонуса строки нет вовсе.

**Выдача**
8. Оплатить тариф с бонусом → доступ **не выдаётся сразу**, на почту приходит письмо со ссылкой.
9. Письмо: тема без имени, в теле «Подарок от: Имя, Бренд», дни цифрой, подпись с `@pluson_bot` и MAX.
10. Перейти по ссылке → кабинет создан, подписка активна, отсчёт с этого момента.
11. Перейти по ссылке ПОВТОРНО → «Доступ уже активирован», второй раз не срабатывает.
12. Тот же сценарий на почту, где кабинет уже есть → продление на 3 дня, тариф не меняется (Профи остаётся Профи).

**Напоминания**
13. Купон не активирован → письма на 3, 14, 30, 60 день и за 7/1 день до сгорания.
14. Активированный купон напоминаний не получает.

**Проверка в базе**
```sql
SELECT email, activated_at IS NOT NULL AS активирован, client_created, outcome, reminders_sent
  FROM plusson_bonus_coupons ORDER BY id DESC LIMIT 10;
```

## PDF: длинные страницы, галерея, очередь (2026-08-18)

1. **Длинный лендинг** (высота больше ~18000 px) → в PDF **одна** страница, заголовки целые.
   Проверка: `python3 -c "import fitz; print(fitz.open('файл.pdf').page_count)"` → должно быть 1.
2. **Галерея-карусель** в PDF: одна карточка + кнопка «СМОТРЕТЬ ЕЩЁ N — НА САЙТЕ».
   Клик по кнопке в файле открывает лендинг на этой же галерее.
3. **Галерея-сетка** (`mode: grid`) в PDF показывается целиком, кнопки нет — так и надо.
4. **Две печати одновременно** (два человека жмут кнопку) → обе завершаются успешно,
   вторая просто ждёт очереди. Ошибки «Браузер не запустился» быть не должно.
5. **Кнопка во время сборки** показывает этап и счётчик секунд, под ней — просьба не
   обновлять страницу. При попытке закрыть вкладку браузер переспрашивает.
