# TESTING.md — Сценарии тестирования ПЛЮСОН

> Этот файл описывает что и как проверять перед деплоем и после изменений.
> Тесты делятся на: ручные сценарии (end-to-end) и проверки по компонентам.

---

## Приоритет тестирования

**Критично (без этого продукт не работает):**
1. Реферальная цепочка: клик → конверсия → начисление баллов → выдача подарка
2. Регистрация участника через бота
3. Mini App открывается и показывает правильный прогресс

**Важно (ключевые функции):**
4. Клиент создаёт событие и получает ссылку
5. Webhook от GetCourse засчитывает конверсию
6. Рассылка участникам уходит в правильный сегмент

**Дополнительно:**
7. Панель администратора показывает актуальные данные
8. Модуль «Конференция» отображает программу и спикеров

## Сценарий 1 — Полный путь Клиента (ручной тест)

**Цель:** убедиться что Клиент может создать событие и получить рабочую реферальную ссылку.

- [ ] Открыть `/register` → зарегистрировать нового клиента
- [ ] Войти через `/login` → попасть в дашборд
- [ ] Нажать «Создать событие» → заполнить форму (шаг 1: название, модуль, подписки)
- [ ] Перейти к шагу 2 → добавить минимум 1 подарок с порогом 1
- [ ] Создать событие → попасть на карточку события
- [ ] Убедиться что реферальная ссылка сгенерирована и отображается
- [ ] Скопировать ссылку → открыть в браузере → убедиться что редирект работает

---

## Сценарий 2 — Полный путь Участника (ручной тест)

**Цель:** убедиться что цепочка реферал → регистрация → подарок работает от начала до конца.

**Подготовка:** создать тестовое событие с подарком на 1 приглашённого.

- [ ] Открыть Telegram → написать боту `/start ref_{ref_code}` (взять код из БД)
- [ ] Бот должен ответить приветствием и кнопкой открытия Mini App
- [ ] Открыть Mini App → проверить что событие отображается в списке
- [ ] Открыть событие → убедиться что [Игра] открывается
- [ ] Проверить что `activated_at` записался в `event_participants`
- [ ] Теперь симулировать «нового участника»: другой аккаунт Telegram открывает бота с тем же `ref_code`
- [ ] Проверить в БД: `referral_events` → появилась запись `type=click`
- [ ] Отправить webhook конверсии: `POST /api/v1/referral/conversion` `{ event_slug, ref_code, type: "free" }`
- [ ] Проверить в БД: `event_participants.points_total` первого участника увеличился
- [ ] Проверить: `gift_issuances` → появилась запись для первого участника
- [ ] Первый участник должен получить уведомление в Telegram о подарке

## Сценарий 3 — Webhook от GetCourse (ручной тест)

**Цель:** убедиться что конверсия засчитывается когда платёжка отправляет webhook.

- [ ] Создать событие с `webhook_url` заполненным
- [ ] Отправить тестовый POST на `/api/v1/referral/conversion`:
  ```json
  {
    "event_slug": "test-event",
    "ref_code": "ABC123",
    "type": "free"
  }
  ```
  С заголовком `X-Webhook-Secret: {WEBHOOK_SECRET}`
- [ ] Ответ должен быть `200 OK`
- [ ] Проверить в БД что баллы начислены

## Проверки API (можно через Postman / curl)

### Авторизация
```
POST /api/v1/auth/register
{ "email": "test@test.com", "password": "Test1234!", "name": "Тест" }
→ ожидается: { "access_token": "...", "token_type": "bearer" }

POST /api/v1/auth/login
{ "email": "test@test.com", "password": "Test1234!" }
→ ожидается: { "access_token": "..." }
```

### События
```
GET /api/v1/events/
Headers: Authorization: Bearer {token}
→ ожидается: [] или список событий клиента

POST /api/v1/events/
Headers: Authorization: Bearer {token}
{ "title": "Тест", "module_slug": "base", "points_free": 1 }
→ ожидается: объект события с id и slug
```

### Участники
```
GET /api/v1/participants/by_tg/123456789
→ ожидается: список событий участника
```

### Health check
```
GET /health
→ ожидается: { "status": "ok" }
```

## Проверки перед деплоем (чеклист)

### База данных
- [ ] Все миграции применены (`db/migrations/001_schema.sql`, `002_indexes.sql`)
- [ ] Seed-данные загружены (`db/seed/001_initial.sql`): тариф Beta, клиент Маргарита

### Bot

- [ ] `/start` без параметра отвечает

- [ ] `.env.local` содержит `NEXT_PUBLIC_API_URL`
- [ ] `/login` → вход работает → `/dashboard` открывается
- [ ] Создание события → сохраняется в БД

### Mini App (Vercel)
- [ ] `VITE_API_URL` установлен
- [ ] Открывается через `t.me/{BOT_NAME}/{APP_NAME}`
- [ ] `twa.initDataUnsafe.user.id` доступен (проверить в Telegram, не в браузере)

## Известные ограничения (не баги)

- Mini App не работает в обычном браузере — только внутри Telegram
- Проверка подписки на канал работает только если бот является администратором канала
- `points_scope = 'client'` (накопительные баллы across событий) — не реализован в MVP
