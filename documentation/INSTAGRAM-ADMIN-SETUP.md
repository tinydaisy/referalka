# Instagram: настройка приложения Meta (админская)

> Что делает ВЛАДЕЛЕЦ ПЛАТФОРМЫ один раз, чтобы Instagram заработал у всех клиентов.
> Клиентская часть (подключить свой аккаунт) — [/dashboard/help/instagram-setup](../web/src/app/dashboard/help/instagram-setup/page.tsx).
> Механика воронки — [INSTAGRAM-FUNNEL-PLAN.md](INSTAGRAM-FUNNEL-PLAN.md).
>
> Настроено 2026-09-07. Приложение **PLUSON**, App ID `947034338456221`.

---

## Что где живёт

| Кто | Что делает |
|---|---|
| **Владелец платформы, один раз** | приложение Meta, ключи, Redirect URI, конфигурация входа, вебхук |
| **Каждый клиент** | Instagram в режиме Бизнес/Автор + связка со страницей Facebook, кнопка «Подключить» в Каналах |

⚠️ Клиент в кабинет разработчика Meta **не заходит вообще**. Приложение одно на всю
платформу; кто прислал событие, определяется по номеру аккаунта внутри самого события.

⚠️ Страницу на вебхук подписывает **код** в момент подключения аккаунта
(`subscribe_page` в [instagram_api.py](../backend/app/services/instagram_api.py)).
Отдельной кнопки нет намеренно: её забыли бы нажать, а сбой молчаливый — воронка
просто не срабатывает.

---

## ⚠️⚠️ Только `graph.facebook.com`

Проверено на прод-сервере 2026-09-03:

```
graph.facebook.com   → отвечает за 0,07 с
graph.instagram.com  → ТАЙМАУТ
api.instagram.com    → ТАЙМАУТ
```

Отсюда жёсткое требование: **«Instagram API with Facebook Login»**. Новый способ Meta
«Instagram API with Instagram Login» живёт как раз на недоступных доменах — у нас он
не заработает без зарубежного прокси.

⚠️ Поэтому разрешения нужны **без приставки `business`**: `instagram_basic`, а не
`instagram_business_basic`. Имена с `business` относятся к другому способу входа,
сколько бы их ни советовали статьи в интернете.

## 1. Приложение

[developers.facebook.com](https://developers.facebook.com) → «Мои приложения» →
«Создать приложение», тип **Бизнес**.

⚠️ **В названии нельзя писать Instagram, Facebook, Meta** — Meta отклоняет.
Наше называется просто `PLUSON`.

Сценарий использования: **«Управление сообщениями и контентом в Instagram»**
(группа «Бизнес-переписка»).

⚠️ Позже пришлось добавить второй сценарий — **«Управляйте всем на своей Странице»**:
без него нет `pages_show_list`, а Instagram-аккаунт находится ТОЛЬКО через страницу.

---

## 2. Разрешения

Добавляются в сценарии: **Панель → «Персонализируйте сценарий…» → «Разрешения и функции»**.
И только потом появляются в списке при создании конфигурации.

| Разрешение | Зачем | Откуда |
|---|---|---|
| `instagram_basic` | найти привязанный к странице аккаунт | сценарий Instagram |
| `instagram_manage_comments` | читать комментарии и отвечать | сценарий Instagram |
| `instagram_manage_messages` | писать в директ | сценарий Instagram |
| `instagram_content_publish` | публикация постов/рилсов/сторис (на будущее) | сценарий Instagram |
| `pages_show_list` | список страниц — без него аккаунт не найти | сценарий Страниц |
| `pages_read_engagement` | данные страницы | сценарий Страниц |
| `business_management` | **страницы бизнес-портфолио** | сценарий Страниц |

⚠️⚠️ **`business_management` обязателен, если страницы лежат в бизнес-портфолио.**
`me/accounts` отдаёт только страницы, которыми человек владеет ЛИЧНО. Страницы
портфолио туда не попадают — приходит пустой список при полностью выданных правах,
и это неотличимо от «страниц нет вовсе». На этом потеряли час 2026-09-07.

⚠️ Статус **«Готово к тестированию»** означает, что разрешение уже доступно —
добавлять его не нужно, кнопки и не будет.

⚠️ **Расширенный доступ (Advanced Access) не запрашивать** — это заявка на проверку
Meta, недели ожидания. Нужен **стандартный**: он работает сразу для аккаунтов,
у которых есть роль в приложении.

## 3. Redirect URI

**Вход через Facebook → Настройки** → поле **«Действительные URI перенаправления для OAuth»**:

```
https://pluson.ru/api/v1/channels/instagram/oauth-callback
```

⚠️ Meta сверяет строку **буквально**, до последнего слэша.

⚠️ Не путать с полем **«Средство проверки URI переадресации»** на той же странице —
оно ничего не сохраняет, только проверяет, есть ли адрес в списке. Список **ниже**.

⚠️ Адрес один на всех клиентов, включая тех, у кого свой домен: Meta принимает только
заранее вписанные адреса. Для человека это незаметно.

## 4. Конфигурация входа

**Вход через Facebook → Конфигурации → Создать конфигурацию.**

| Шаг | Что выбрать |
|---|---|
| Маркер доступа | **Маркер доступа пользователя** |
| Объекты | пропускаются (для пользовательского маркера их не выбирают) |
| Разрешения | все семь из таблицы выше |

⚠️⚠️ **В Business Login разрешения передаются `config_id`, а НЕ параметром `scope`.**
Со `scope` Meta отвечает «Invalid Scopes» и перечисляет ВСЕ переданные разрешения как
недействительные — выглядит так, будто имена устарели, хотя дело в способе передачи.
Не возвращать `scope` в [instagram_api.oauth_url](../backend/app/services/instagram_api.py).

⚠️ **Тип маркера после создания не изменить** — только пересоздавать конфигурацию.

⚠️ Пробовали системный маркер (он требует бизнес-портфолио) — **отказались**: у клиента
портфолио может не быть вовсе, а вход через личный Facebook понятнее. Пустой список
разрешений был не из-за типа маркера, а из-за того, что их не добавили в сценарий.

Configuration ID → в переменные окружения (`IG_CONFIG_ID`).

## 5. Вебхук

⚠️⚠️ **ПОДПИСОК ДВЕ, и нужны обе.** Это разные вещи, и одна без другой не работает:

| Что | Кто делает | Где смотреть |
|---|---|---|
| **Приложение** подписано на поля | **человек, руками** в кабинете Meta | `GET /{app-id}/subscriptions` |
| **Страница** подписана на приложение | **код**, при подключении аккаунта | `GET /{page-id}/subscribed_apps` |

Пока не сделаны обе — Meta не пришлёт ни одного события, и воронка молчит на
любой комментарий. Проверять надо обе, а не одну:

```bash
# приложение (пусто = не подписано, самая частая причина тишины)
curl -s "https://graph.facebook.com/v21.0/<APP_ID>/subscriptions?access_token=<APP_ID>|<SECRET>"

# страница
curl -s "https://graph.facebook.com/v21.0/<PAGE_ID>/subscribed_apps?access_token=<PAGE_TOKEN>"
```

⚠️⚠️ **Поле подписки СТРАНИЦЫ называется `feed`, а НЕ `comments`.** Документация
Meta говорит `comments`, но при подписке страницы Facebook оно отвергается:
«must be one of {feed, mention, …}». Проверено живым запросом 2026-09-07.
Комментарии Instagram приходят через `feed`, и в событии у них другие ключи:
`post_id` вместо `media.id`, `message` вместо `text` — разбор принимает оба
набора.

⚠️⚠️ **`messages` требует отдельного разрешения `pages_messaging`.** Без него
подписка падала ЦЕЛИКОМ — даже на комментарии. Поэтому подписываемся по одному
полю за раз: комментарии основа воронки, терять их из-за недостающего
разрешения на директ нельзя.



Внутри сценария: **Панель → «Персонализируйте сценарий использования "Управление
сообщениями и контентом в Instagram"» → Вебхуки**.

| Поле | Значение |
|---|---|
| Callback URL | `https://pluson.ru/api/v1/instagram/webhook` |
| Verify Token | считается из секрета приложения, см. ниже |

Подписаться на поля: **`comments`** и **`messages`**.

Токен подтверждения:

```bash
cd /var/www/plusson/backend && source /var/www/plusson/venv/bin/activate
python3 -c "import sys; sys.path.insert(0,'.'); \
  from app.api.instagram_webhook import _verify_token; print(_verify_token())"
```

⚠️ Отдельной переменной для него нет намеренно: ещё один секрет — ещё одно место, где
он разъедется между сервером и кабинетом Meta. Он производная от `IG_APP_SECRET`,
и при смене секрета **токен в кабинете Meta надо обновить**.

⚠️ Подпись запросов (`X-Hub-Signature-256`) проверяется всегда. Без неё любой, зная
публичный адрес вебхука, слал бы поддельные комментарии и вытаскивал материалы клиентов.

## 6. Переменные окружения

`/var/www/plusson/backend/.env`:

```
IG_APP_ID=947034338456221
IG_APP_SECRET=<Настройки → Основное → Секрет приложения>
IG_CONFIG_ID=<Вход через Facebook → Конфигурации>

```

После правки — `systemctl restart plusson-api`.

⚠️ `IG_CONFIG_ID` проверяется наравне с ключами (`is_configured`): без него окно
Facebook откроется, но БЕЗ единого разрешения — человек пройдёт вход и упрётся
в «нет доступа» уже после, когда причину не видно.

## 7. Роли и проверка Meta

⚠️⚠️ **Пока фича на тарифе `admin`, проверку Meta проходить НЕ НУЖНО.** Приложение в
режиме разработки полноценно работает с аккаунтами, у которых есть **роль в нём**
(администратор / разработчик / тестировщик).

Создатель приложения — уже администратор, добавлять себя никуда не надо.
Роли нужны только другому человеку: **Роли в приложении → Добавить людей**, и ему —
**«Тестировщик»**, не администратор (тот может удалить приложение и сменить ключи).

App Review понадобится, только когда фичу откроют клиентам. Тогда на каждое разрешение
нужно видео-демо — ещё одна причина не набирать лишних.

## Что ломалось и почему (чтобы не повторять)

| Симптом | Причина |
|---|---|
| «Invalid Scopes» со всеми разрешениями | передавали `scope` вместо `config_id` |
| Разрешений нет в списке конфигурации | не добавлены в сценарий |
| «У вас нет страниц Facebook» | нет `pages_show_list` — страницы есть, их не видно |
| Страниц нет при выданном `pages_show_list` | страницы в бизнес-портфолио, нужен `business_management` |
| Страницы нашлись, «Instagram не привязан» | нет `instagram_basic` — связку не видно |
| Вернулся в Каналы, ничего не произошло | результат читал компонент внутри закрытой формы |
| Подписка страницы падает целиком | передавали `comments` — принимается только `feed` |
| Подписка падает даже на комментарии | в одном запросе шло `messages`, а `pages_messaging` не выдан |
| Вебхуков ноль при подписанной странице | **приложение** не подписано на поля (это вторая, отдельная подписка) |
| Удалил канал — пропали воронки | `ON DELETE CASCADE` на `channel_id`, исправлено миграцией 368 |

⚠️ Общее правило: **сообщение «у вас нет X» почти всегда означает «мы не видим X»**.
Тексты ошибок в [channels.py](../backend/app/api/channels.py) переписаны так, чтобы
не отправлять человека чинить исправное, и показывают список выданных прав.

## Диагностика

```bash
# что реально пришло с токеном (при неудачном подключении пишется в лог)
journalctl -u plusson-api --since '15 min ago' | grep instagram.oauth

# ссылка входа собирается верно?
cd /var/www/plusson/backend && source /var/www/plusson/venv/bin/activate
python3 -c "import sys; sys.path.insert(0,'.'); from app.services import instagram_api as ig; \
  print(ig.is_configured()); print(ig.oauth_url('TEST')[:160])"

# подключённые аккаунты
sudo -u postgres psql -d plusson -c \
  "SELECT id, handle, platform_meta->>'ig_user_id', platform_meta->>'followers' \
     FROM channels WHERE platform_slug='instagram'"
```

⚠️ **Токен живёт 60 дней**, продлевает Celery (`app.tasks.instagram.refresh_tokens`,
раз в сутки, за 10 дней до конца). Без задачи воронка через два месяца молча
затихает — не ломается заметно, а просто перестаёт отвечать людям.
