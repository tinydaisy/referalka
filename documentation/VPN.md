# VPN.md — Свой VPN на сервере ПЛЮСОН

> Собственный WireGuard-сервер на проде для выхода в интернет с российского IP.
> Установлен 08.09.2026. Нужен, когда владелец за границей, а зайти надо на российские сервисы.

---

## Что это и зачем

На прод-сервере (`194.156.119.17`, Москва, Beget) поднят **WireGuard** — VPN-сервер. Подключаетесь к нему с телефона или компьютера, и весь интернет-трафик идёт через московский адрес: сайты видят вас как пользователя из России.

**Задача, ради которой ставили:** зайти в российские банки и на Госуслуги, находясь за границей — оттуда они часто не открываются вовсе.

---

## ⚠️ Что работает, а что нет — проверено на живых сервисах

Не все российские сервисы пускают через этот VPN, и это **нельзя починить настройкой**. Причина — банки блокируют не страну, а **тип адреса**: наш сервер стоит на коммерческом хостинге (Beget), и часть банков режет такие адреса целиком, чтобы отсекать ботов и мошенников.

| Сервис | Через VPN | Проверено |
|---|---|---|
| **Госуслуги** | ✅ работает | 08.09.2026 |
| **Сбербанк** | ✅ работает | 08.09.2026 |
| **ВТБ** | ❌ не открывается | 08.09.2026 |
| **Альфа-банк** | ❌ не открывается | 08.09.2026 |

⚠️ **У ВТБ и Альфы соединение не устанавливается физически** — порт закрыт, пинг не проходит (100% потерь пакетов). Это отказ на их стороне, а не сбой VPN.

⚠️⚠️ **Код ответа 302 — НЕ признак того, что сайт открывается.** На этом легко ошибиться: `curl -I` отдаёт по ВТБ бодрый `302`, и кажется, что всё хорошо. Но `302` — это просто «перейдите по адресу», а если пройти по нему до конца (`curl -L`), приходит `000` и **ноль байт**. Проверять доступность надо полным заходом с переходами, а не заголовком:

```bash
# ПРАВИЛЬНО — идём до конца, как браузер
curl -s -o /dev/null -w "%{http_code}\n" --max-time 25 -L -A "Mozilla/5.0" https://online.vtb.ru/

# НЕДОСТАТОЧНО — покажет обманчивый 302
curl -I https://online.vtb.ru/
```

**Если нужен именно ВТБ** — этот VPN не поможет, и донастройка ничего не изменит. Любой VPN на любом хостинге упрётся в то же самое. Варианты: домашний роутер у знакомых в России (даёт настоящий домашний IP), либо звонок в банк с просьбой разрешить вход из-за границы.

## Как подключиться

### Телефон

1. Установить приложение **WireGuard** (App Store / Google Play, бесплатное).
2. **+** → **«Создать из QR-кода»** → навести на QR-код.
3. Дать имя туннелю → включить тумблер.

### Компьютер (Mac)

1. Установить **WireGuard** из App Store.
2. Слева внизу **«+»** → **«Импортировать туннели из файла»** → выбрать `компьютер.conf`.
3. Нажать **«Подключить»**.

Первый раз macOS попросит разрешение на VPN-конфигурацию и пароль от компьютера — это нормально, так система защищает сетевые настройки.

### Проверка, что работает

Зайти на **2ip.ru** — должно показать **194.156.119.17, Москва**. Если показывает вашу настоящую страну, VPN не подключён.

## ⚠️ Где лежат ключи

**Конфиги в git НЕ хранятся и храниться не должны** — это ключи от сервера: у кого файл, тот выходит в интернет под нашим IP.

| Что | Где |
|---|---|
| Конфиги и ключи | на сервере, `/etc/wireguard/` (права `600`, только root) |
| Копии для подключения | у владельца на рабочем столе, папка `VPN-ПЛЮСОН` |

Файлы на сервере: `wg0.conf` (конфиг сервера), `clients/phone.conf`, `clients/laptop.conf`.

## Как устроено

| Параметр | Значение |
|---|---|
| Протокол | WireGuard |
| Порт | `51820/UDP` |
| Внутренняя сеть | `10.66.66.0/24` |
| Телефон | `10.66.66.2` |
| Компьютер | `10.66.66.3` |
| Внешний интерфейс | `eth0` |
| Служба systemd | `wg-quick@wg0` (автозапуск включён) |

Трафик клиентов выпускается наружу через NAT (`MASQUERADE` на `eth0`), правила поднимаются и снимаются вместе со службой через `PostUp`/`PostDown` в `wg0.conf`. Пересылка включена в `/etc/sysctl.d/99-wireguard.conf`.

У каждого клиента свой ключ **и свой preshared-ключ** — дополнительный слой поверх основного шифрования.

## Обслуживание

```bash
# Кто подключён, когда было последнее рукопожатие, сколько трафика
wg show wg0

# Состояние службы
systemctl status wg-quick@wg0

# Перезапуск (клиенты переподключатся сами)
systemctl restart wg-quick@wg0
```

⚠️ **`wg show` — единственный честный способ проверить, подключено ли устройство.** Смотреть на `latest handshake`: если рукопожатия нет вовсе или оно многочасовой давности — устройство не подключено, что бы ни показывало приложение. Peer без строки `endpoint` не подключался ни разу.

### Добавить устройство

```bash
cd /etc/wireguard
umask 077
NAME=tablet; IP=10.66.66.4          # следующий свободный адрес
wg genkey | tee clients/${NAME}_private.key | wg pubkey > clients/${NAME}_public.key
wg genpsk > clients/${NAME}_psk.key

# Прописать peer в wg0.conf (секция [Peer] с AllowedIPs = ${IP}/32), затем:
systemctl restart wg-quick@wg0

# QR-код для телефона
qrencode -t ansiutf8 < clients/${NAME}.conf
```

Конфиг клиента собирается по образцу существующих: `PrivateKey` устройства, `Address = ${IP}/32`, `DNS = 1.1.1.1, 8.8.8.8`, в `[Peer]` — публичный ключ сервера, preshared-ключ, `Endpoint = 194.156.119.17:51820`, `AllowedIPs = 0.0.0.0/0`, `PersistentKeepalive = 25`.

## ⚠️ Риски, о которых надо помнить

⚠️⚠️ **С этого IP уходит почта всей платформы.** Раздавать конфиги посторонним нельзя: чужой трафик может утащить `194.156.119.17` в спам-списки, и просядет доставляемость писем клиентам — рассылки, регистрации, восстановление пароля. Пока пользуется один владелец, риск невелик.

⚠️ **VPN пропускает весь трафик устройства**, а не только браузер. Выключается тумблером в приложении.

⚠️ **Порт `51820/UDP` открыт наружу** — это ещё одна точка входа на прод-сервер. Защита строится на ключах: без приватного ключа подключиться нельзя, пароля здесь нет вовсе.

⚠️ **Нагрузки на сервер практически нет** — WireGuard работает в ядре. После установки замерено: сайт отвечает за 3 секунды, load average 0.04, все сервисы (`plusson-api`, `plusson-web`, `plusson-bot`, `plusson-celery`, `plusson-celery-beat`) живы.

⚠️ **Банк увидит вход из Москвы, хотя вы за границей** — в этом и смысл. Но если банк потребует подтверждение по СМС, российский номер должен принимать сообщения: за границей без роуминга они не дойдут.

## Установка с нуля (если переезд на другой сервер)

```bash
apt-get install -y wireguard wireguard-tools qrencode

cd /etc/wireguard && umask 077
wg genkey | tee server_private.key | wg pubkey > server_public.key

echo "net.ipv4.ip_forward = 1" > /etc/sysctl.d/99-wireguard.conf
sysctl -p /etc/sysctl.d/99-wireguard.conf

# Собрать wg0.conf (см. раздел «Как устроено»), затем:
systemctl enable --now wg-quick@wg0
```

⚠️ **Имя внешнего интерфейса проверять, а не брать из этого файла** — на другом сервере оно может быть не `eth0`:

```bash
ip route | grep default
```

Ошибётесь в имени — NAT не заработает: VPN подключится, но интернета у клиентов не будет.
