> Живой документ. Каждая итерация архитектуры → запись с датой, что попробовали, у кого что сломалось, что узнали.

## TL;DR (текущий статус на 2026-05-19)

- **Свет, Гульшат, Тотелла, Евгения** — четверо юзеров, у каждой **своя** причина «не открывается»
- Перепробованы: Beget direct (до 2026-05-14), Cloudflare поверх Beget (2026-05-14 → 2026-05-19), Yandex CDN (тест 2026-05-18→19), **Beget direct без CF (текущее, с 2026-05-19)**
- **🔑 КЛЮЧЕВОЕ ОТКРЫТИЕ 2026-05-19:** Евгения с VPN не открывает НИ ОДИН URL (pluson.ru, test.pluson.ru, ivision.pluson.ru). БЕЗ VPN — всё открывается. То есть **её проблема — её VPN, не наша инфра**. Это объясняет ту самую «20% VPN-юзеров не открывали Beget».
- **GetCourse у всех работает** даже с VPN, потому что у них российский VPS с хорошим peering (Selectel/Mail.ru). Beget peering хуже для некоторых VPN-маршрутов.
- **Текущее состояние архитектуры:** `pluson.ru` → Beget direct (без CF, HTTP/1.1). Это «как GetCourse». Работает для всех RU-юзеров без VPN. Для VPN-юзеров — зависит от их VPN-маршрута.
- **Следующий шаг:** проверить тот же тест у Свет/Гульшат/Тотеллы (без VPN). Если у них Beget direct работает → остаёмся. Если кто-то всё ещё ломается → переезд на Selectel.

## Хронология архитектурных решений

### До 2026-05-14 — Beget direct
- DNS `pluson.ru` → `194.156.119.17` (Beget VPS, российский хостинг)
- nginx HTTP/1.1 (HTTP/2 не включался в listen-директивах)
- Без CDN
- **Известная проблема:** «~20% пользователей с VPN не открывали сайт» (зафиксировано в `memory/project_cloudflare_setup.md`). Причина точно не установлена — возможно plохой peering Beget с зарубежными сетями, или специфические VPN-маршруты с блок-листами.

### 2026-05-14 — миграция на Cloudflare
- DNS перенесён в Cloudflare (`brianna.ns.cloudflare.com` / `razvan.ns.cloudflare.com`)
- `pluson.ru`, `www.pluson.ru`, `dev.pluson.ru`, `ivision.pluson.ru` — все Proxied (оранжевая туча)
- CF → Beget origin
- **Цель миграции:** починить «20% VPN-юзеров»
- **Что выключено в CF** (потому что иначе режет пользователей): HTTP/3 (QUIC), 0-RTT, Browser Integrity Check, Bot Fight Mode. SSL/TLS режим Full (strict).
- **Аккаунт CF:** `margarita.forbs1@gmail.com`
- **Подробности:** `memory/project_cloudflare_setup.md`, `documentation/CLOUDFLARE-SETUP.md`

### 2026-05-17 — оптимизация ассетов ivision.pluson.ru
Жалоба Евгении (@EvgeniyAlexsa) что лендинг конференции зависает. Расследование показало:
- 33+ МБ начальной загрузки (огромные PNG-картинки 2-5 МБ каждая, видео `smeh.mp4` 5.9 МБ автоплей, видео preload=metadata тащит 14 файлов параллельно)
- Telegram-webview ломал большие TCP connection pool, OOM на больших PNG → ERR_TIMED_OUT
- **Деплой 2026-05-17 18:00 UTC:** 17 картинок пережаты PNG/JPG → WebP/JPEG на R2 (35.6 МБ → 1.7 МБ), `smeh.mp4` пережат ffmpeg (5.9 МБ → 737 КБ), видео получили `preload="none"`, постеры 12 видео сгенерированы как `.jpg` на R2
- Начальная загрузка лендинга: ~33 МБ → ~4 МБ
- Коммиты в `tinydaisy/ivision-conf`: `ee376d9`, `eed9def`, `2062797`

### 2026-05-17 — fix /r/{slug} (Tilda overlay)

- Коммит `91f878c` в `tinydaisy/referalka`, деплой на прод + dev

## Что мы знаем точно

1. **GetCourse работает у всех пользователей** — Свет, Гульшат, Тотелла, эмигранты с VPN, в любой стране. Это бенчмарк.
2. **Архитектура GetCourse:**
   - Российский VPS (вероятно Selectel или Mail.ru Cloud), IP вроде `178.248.237.90`
   - nginx с **HTTP/1.1** (явно отказались от HTTP/2)
   - Без внешнего CDN
   - HTTPS с Let's Encrypt-подобным cert
   - Российские IP не в блок-листах VPN-провайдеров и не блокируются российскими провайдерами
3. **Наш Beget уже HTTP/1.1** (`nginx 1.24`, в `listen 443 ssl;` нет `http2`). Это значит когда были «20% VPN-юзеров не открывали Beget» — это уже было на HTTP/1.1. Проблема была не в протоколе.
4. **Cloudflare** ломает Свету (её провайдер режет CF-IP) и Гульшат (тяжёлые ассеты не пропускаются).
5. **Yandex CDN** ломает Тотеллу (HTTP/2 PING-ошибки между её устройством и Yandex edge).
6. Все три CDN-варианта (CF, Yandex CDN, Beget direct) каждый имеет свою категорию ломающихся юзеров.

## Чего мы НЕ знаем

1. **Почему именно Beget не пробивал «20% VPN-юзеров»** — peering, блок-листы у VPN, специфика маршрутов? Не выяснено.
2. **Сработает ли Beget direct + HTTP/1.1 без CF у всех** — гипотеза, не проверена тестом.
3. **Реальный процент ломающихся юзеров** на каждой архитектуре — мы видим только тех кто пишет в поддержку.

## Текущая гипотеза (обновлена 2026-05-19 после теста с Евгенией)

**Гипотеза (текущая, нуждается в проверке на других юзерах):**
- **Без VPN** Beget RU direct (с HTTP/1.1, без CF) **работает у RU-юзеров** — подтверждено на Евгении (без VPN всё открылось)
- **С VPN** в некоторых случаях ломается из-за плохого peering между конкретным VPN-exit и Beget RU IP. Это та самая «20% VPN-юзеров не открывали Beget» история — она реальна и связана с тем какой именно VPN-сервис использует пользователь
- Cloudflare помогал части VPN-юзеров (потому что CF имеет глобальные edges и любой VPN-exit обычно нормально достигает CF), но **создавал проблемы для RU-юзеров с CF-блокирующими провайдерами** (Свет)
- Получается: нет универсального решения «один CDN/хостинг для всех»

**GetCourse работает у всех** потому что:
1. Российский VPS (Selectel/Mail.ru Cloud) с **хорошим peering и для RU-сетей и для зарубежных** (в отличие от Beget)
2. HTTP/1.1 (без проблем DPI с HTTP/2 PING)
3. Без CDN (без CF-блокирующих провайдеров)

**Если хотим как GetCourse — переезд на Selectel / Mail.ru Cloud / Yandex Cloud Compute.** Это **миграция инфры**, 2-3 рабочих дня.

## План решений (обновлён 2026-05-19)

| Сценарий | Что делаем |
|---|---|
| Большинство юзеров на Beget direct работают без VPN | ✅ Текущее состояние работает для большинства. Остаёмся как есть. |
| Юзеры с VPN ломаются на Beget direct | Им рекомендуем выключить VPN при пользовании платформой (как сделала Евгения) — у RU-аудитории Pluson VPN не обязателен. ИЛИ переезжаем на Selectel где peering лучше для VPN тоже. |

| Долгосрочно — мультиплатформа (VK, MAX) | Та же инфра. Если pluson.ru на Selectel — все Mini Apps будут работать у всех. |

## Чек-лист тестирования при каждом архитектурном изменении

1. Открыть из России на обычном провайдере (МТС, Билайн, Мегафон, Ростелеком) — без VPN
2. Открыть из России на провайдере который режет CF (Дом.ру, ТТК) — без VPN
3. Открыть с включённым VPN (зарубежный exit) из России
4. Открыть физически из-за границы (Таиланд, Турция, ОАЭ) без VPN
5. Открыть в Telegram in-app webview (Android, iOS)
6. Открыть в Mini App: проверить что JS-бандл докачивается, не виснет на splash
7. Открыть платёжный flow: /r/{slug} после Tilda/GetCourse редиректа
8. Проверить ивентовый лендинг: `pluson.ru/l/{slug}?app=tg`
9. Проверить сторонний лендинг: `ivision.pluson.ru/kreativ-chempionat`

Без этого чек-листа любое архитектурное изменение чинит одних и ломает других.
