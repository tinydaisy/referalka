## 1. Зачем это вообще (главная боль клиента)

Клиент платит за ПЛЮСОН (990 ₽/мес) и сегодня получает работу со **своей** базой: выдачу лид-магнитов за подписку, рассылки, реф-программу «приведи друга». Это ядро, оно работает.

Но клиент говорит честно:

> «На свою аудиторию я и так пост в канале выдам. Мне нужно показать свой лид-магнит **чужой** аудитории — иначе зачем мне сервис.»

При этом клиент **не готов**:
- пиарить чужое в своём канале («продаю чужое» — так провалился прошлый опыт);
- рекламировать абстрактный сервис «за бонусы», которые не превращаются в подписчиков.

Клиент **легко готов**:
- прорекламить сам сервис своей аудитории, если это «прикольная штука с забавной системой коллабораций»;
- получить чужую аудиторию, если механизм встроен в сервис и не требует ручного пиара чужого.

**Вывод:** нужен слой, где «чужим каналом, который показывает твой лид-магнит» становится **сам сервис**, а не другой эксперт. И где рост аудитории происходит **внутри** платформы, по согласию, без принуждения пиарить чужое.

## 2. Два слоя продукта (ключевая развязка монетизации)

Продукт делится на два слоя, которые кормят друг друга:

### Слой 1 — БЕСПЛАТНЫЙ виральный вход (рефералка-цепочка)

Машина привлечения новых людей с улицы. Полностью бесплатна.

1. Эксперт/бизнес рекламирует **сам сервис** своей аудитории (легко, не стыдно, чужое не пиарит).
2. Человек заходит по ссылке **в сервис**. Внутри сервиса (не в чьём-то канале — все показы внутри платформы) ему показывают **список лид-магнитов из его цепочки: до 7 человек над ним**.
3. Он **обязан выбрать минимум 3** (может все), подписаться. Это плата за вход. Окажется неинтересным — отпишется, но факт показа уже состоялся.
4. После этого он **сам встаёт в цепочку** (его лид-магнит будет показан тем, кто зайдёт под ним) и **попадает в общую базу коллабораций**.

**Почему цепочка из 7, а не лента по рейтингу:**
- В ленте по рейтингу новичку не пробиться — «старенькие» забивают показы.
- В цепочке каждый **гарантированно** показывается всем, кто зайдёт под ним. Видимость растёт вместе с веткой, без борьбы за место.
- «Выбрать 3 из 7» (а не «обязан на всех 7») — предохранитель от мёртвых душ: человек выбирает сам, подписки живее.

**Что даёт по цифрам (грубая прикидка):** ~120 показов за 4 уровня под тобой → выбор 3 из 7 ≈ 43% подписок → минус отписки ≈ **~26 живых чужих подписчиков** без усилий, только за одну рекламу сервиса. Это и есть «показать свой лид-магнит чужим».

Бесплатный участник может **смотреть** и **быть в базе** — пассивно.

### Слой 2 — ПЛАТНЫЙ продукт (990 ₽/мес)

То, ради чего апгрейдятся. Любое **активное** действие + всё ядро ПЛЮСОНа.

| Бесплатно (быть в системе) | 990 ₽/мес (пользоваться системой) |
|---|---|
| Вход по цепочке, выбор 3/7 | Сам предложить коллаб |
| Виден в базе | Умный сват (поиск партнёра) |
| Твой лид-магнит в цепочке (пассивный рост) | Участие в турнире коллабораций |
| Смотреть, что внутри | PRO-видимость (выше в базе) |
| | Аналитика партнёров |
| | Всё ядро ПЛЮСОНа: своя база, рассылки, лид-магниты, Mini App |

**Правило границы:** *быть в системе — бесплатно, пользоваться системой — платно.* Бесплатный слой максимально вирусит (низкий порог = больше масса), платный собирает деньги с тех, кому надо работать.

**Связка двух слоёв:** бесплатная цепочка засасывает тысячи новых людей → они видят живой нетворк → хотят действовать → платят 990 → становятся клиентами ПЛЮСОНа. **Рефералка — это не отдельная фича, а бесплатная воронка, которая приводит платящих клиентов в основной продукт.**

⚠️ Не перегружать бесплатный слой ценностью — иначе никто не доплатит. Граница жёсткая и логичная.

## 3. База коллабораций — фундамент

Каталог участников. Карточка зависит от типа участника:

**Эксперт / инфобизнес:** ниша + размер аудитории + рейтинг + лид-магниты + готовность к форматам коллабораций.

**Твёрдый бизнес (салон, ресторан, магазин, фитнес):** тип бизнеса + ЦА (пол / возраст / гео / доход) + размер базы + **какой ресурс готов дать партнёру** (скидку клиентам партнёра, место под флаер, пост в своём канале).

Это **одна биржа, два сегмента.** Разница только в карточке и критериях матчинга.

> **Кросс-маркетинг для твёрдого бизнеса может оказаться более сильным рынком, чем эксперты:** бизнесов больше, боль острее (нет трафика), совпадение ЦА считается по объективным полям, а не «на глаз». Салону не нужен эфир с салоном-конкурентом — ему нужна коллаборация с рестораном/фитнесом, у которых **та же ЦА, но не конкурент**. Инструменты ПЛЮСОНа (лид-магнит = скидка за подписку, рассылки, реф-программа «приведи подругу») твёрдому бизнесу заходят даже лучше, чем экспертам.

## 4. Рейтинг коллаборатора — мотор

Рейтинг ради рейтинга — мёртвый. Рейтинг должен **открывать двери:**

- **Видимость** — выше в поиске базы, тебя находят первым.
- **Доступ к лиге сильнее** — коллаб с топом доступен только тем, кто сам дорос (защита топов от новичков: нельзя слабому звать миллионника — сольётся). Это и морковка: расти, чтобы получить доступ к лиге выше.
- **Бонусные показы** (внутренняя валюта, см. §6).
- **Бейдж доверия** — «провёл 30 коллабов, не сливался».

**Смысл рейтинга:** «с этим человеком безопасно коллабиться — он приводит живых и не сольётся».

**Растёт за:**
- приведённые **живые** (подписался и не отписался за неделю — не просто зашёл);
- проведённые коллаборации;
- **кто на совместное событие привёл больше людей — тому больше рейтинга** (у совместного события две реф-ссылки, считаем по каждой). Это лечит халявщиков-«прицепщиков»: нельзя присосаться к сильному и ничего не делать — система видит, что ты привёл 0.

## 5. Умный сват и форматы коллабораций

**Не «тайная коллаборация вслепую»** — обмен аудиторией не с кем попало бессмысленен (случайный партнёр не из ниши = пустой обмен).

**Умный сват:** сервис сам подбирает партнёра по **нише/типу + сопоставимый размер аудитории/базы + рейтинг + гео** (для твёрдого бизнеса). «Вот 3 человека, ваши аудитории совпадают на 70%, предложить в один клик». Снимает главную боль коллабораций — лень искать и договариваться.

**Интрига безопасна на уровне темы, не партнёра:** партнёр подобран по совпадению, а **тема — сюрприз** от сервиса. Понравившийся пример: *«вам выпало: разберите ошибки друг друга».* Рискуешь не аудиторией, а только темой разговора.

**Форматы:**
- Эксперты: совместный эфир/вебинар (главный — обе аудитории видят обоих), совместный лид-магнит, розыгрыш «подпишись на обоих», эстафета сторис.
- Твёрдый бизнес: взаимная скидка клиентам, флаер партнёра, совместная акция.

**Где проводят:** где хотят (сторонний зум, офлайн). ПЛЮСОН — **счётчик и табло**, а не место проведения. Событие оформляют через ПЛЮСОН → он даёт реф-ссылки → считает приходы по каждой → начисляет рейтинг.

## 6. Деньги — что работает, что под запретом

**Источники дохода сервису:**
- ✅ **990 ₽/мес** — основной рекуррентный поток (платный слой, §2).
- ✅ **Платная реклама по всей базе** — показать свой лид-магнит всей базе (не только цепочке). Комиссия сервиса.
- ✅ **PRO-статус** — быть выше в базе, чаще в выдаче. Рекуррентно.
- ✅ **Premium-аналитика партнёра** — платят НЕ за «размер аудитории» (виден бесплатно), а за скрытое: сколько коллабов провёл и не слился, конверсия в живых, отзывы. Фильтр «найди партнёра с конверсией >30% в моей нише».
- ✅ **Турнир** — платный вход (взнос), спонсор турнира, PRO-доступ к таблице.

**Внутренняя валюта (баллы) — ТОЛЬКО замкнутый контур:**
- Заработал активностью (привёл живых, провёл коллаб, твой лид-магнит забирают) → тратишь на **показы** (бесплатная реклама).
- Не заработал → платишь рублём.
- ❌ **Баллы НЕ конвертируются в реальные деньги.** Вывод внутренней валюты в рубли = ст. 172.2 УК (финансовая пирамида) + ст. 27 о денежных суррогатах. Мина.
- Два контура нельзя соединять: рубли входят с одного конца (реклама/PRO/990) → сервису; баллы крутятся отдельно.

## 7. Турнир коллабораций (опционально, как «троянский конь»)

Не турнир спикеров, а турнир **совместных эфиров/акций.** За период эксперты/бизнесы делают коллаборации, набирают очки (по живым приведённым), турнирная таблица в реальном времени, в конце — победители.

**Зачем:** дедлайн + соревнование + публичное табло заставляют **делать коллабы сейчас**, а не «когда-нибудь». Превращает рейтинг из «забавной цифры» в азартное событие.

**Деньги участникам** (НЕ призовой фонд из взносов — это лотерея, ст. 1057 ГК, оформляется отдельно): главный приз = **бесплатные показы лид-магнита всей базе** + статус чемпиона + приз от спонсора (легально — дарит спонсор) + доступ в лигу топов.

**Турнир может быть первым кирпичом** (а не база): есть дедлайн, сам наполняет базу, сразу денежный (взносы), а модуль `turnir` в ПЛЮСОНе **уже есть**.

## 8. Что уже работает в ПЛЮСОНе под эту концепцию

- **Воронки выдачи лид-магнитов** (бот: приветствие → проверка подписки → выдача → дожим). Готова основа «лид-магнит за подписку».
- **`funnel_runs`** — логирует landed/started/delivered. Готовая аналитика конверсии для рейтинга.
- **Обязательная подписка на каналы организаторов** (`backend/app/api/subscription_check.py`, режимы `organizer` / `all_speakers`). **Это ключевая ценность участникам:** при входе в чат события человек обязан подписаться на каналы организаторов. Значит аудитория растёт **со всех, кто проявил интерес к событию**, а не только с досмотревших эфир. Честный обмен аудиторией на совместном событии. (Работает при условии: бот — админ в каналах организаторов.)
- **Двойная принадлежность контакта уже встроена** (архитектура G): один `tg_id` нормально живёт у нескольких клиентов одновременно. Совместное событие не ломает модель контактов.
- **`clients.partner_code`** — поле «откуда пришёл клиент». Зацепка под учёт цепочки.
- **Модуль `turnir`** — основа турнирной механики.

### Рейтинг — упрощённая формула v1 (предложение пользователя, считается из готовых данных)
- **Кол-во проведённых коллабораций** (цифра) — число совместных событий, где он организатор.
- **Средний % вклада** = `привёл по своей реф-ссылке / всего участников события`, усреднённо по его событиям. Реф-ссылки + `event_participants` это уже считают.
- ⚠️ Считать **живых** привёл (подписался и не отписался), а не просто зашедших — иначе накрутят.
- Плюс на карточке: история коллабораций (где, с кем, что за событие, результат) + отзывы.

## 9. Что нужно будет реализовать (потом, не сейчас)

### 🔒 ЖЁСТКОЕ ПРАВИЛО (решение пользователя 2026-06-09): совместные события — ТОЛЬКО через @pluson_bot
Добавить коллаборатора-клиента в своё событие можно, **только если событие идёт через бот ПЛЮСОНа** (не через VIP-бот клиента). Почему это снимает всю боль:
- Если у двоих свои VIP-боты — нерешаемо: в чей бот регается участник, чей Mini App, чьи уведомления.
- Решение: совместные события всегда в нейтральном @pluson_bot → оба клиента в одном боте → участник регается в общий → аудитория считается честно по реф-ссылкам каждого → конфликта ботов НЕТ.
- Экономит недели работы. Не отступать от этого правила.

### Co-ownership (несколько организаторов-клиентов на событие)

**Совместное событие двух клиентов ПЛЮСОНа** — техническая основа под совместные эфиры/коллаборации:
- Junction `event_owners(event_id, client_id)` + права редактирования (middleware про co-ownership). `events` сейчас имеет один `client_id` в строке — это умеренная правка.
- Человек на совместном событии приписывается к двум клиентам — **как уже работает** для одного tg_id у разных клиентов (модель контактов трогать НЕ надо).
- В базу бота соорганизатору идут **только реально подписавшиеся**, не все участники.
- Лимиты — пополам.
- У каждого организатора своя реф-ссылка — это и есть «2 ссылки» для подсчёта вклада в коллаб.

> co-ownership = одна техническая основа под совместные эфиры, турнир и биржу. Делать вместе, не порознь.

**Слой биржи и рефералки** — цепочка входа, база с карточками, рейтинг, умный сват, денежные механики. Строить после проверки гипотезы.

## 10. Главные риски и принципы (уроки обсуждения)

- **Не строить вертикальную пирамиду «подпишись на 7 над тобой» силой** — мёртвые подписчики, 95% нижних в проигрыше, не масштабируется. Спасение — «выбрать 3 из 7» + база коллабораций как пряник + реклама **только сервиса**, не чужого.
- **Никого не заставлять пиарить чужое** в своём канале. Рекламируется только сервис.
- **Внутренняя валюта не обналичивается** — юридическая мина.
- **Гипотеза «как быстро запарит делать коллабы» не проверена.** Проверить на 10 живых участниках руками до крупных вложений. Лёгкие форматы (15-мин эфир, пост, розыгрыш) не парят; тяжёлый еженедельный вебинар — выгорают.
- **Не давать неготовому продукту №2 (биржа) сожрать фокус с готового продукта №1 (ПЛЮСОН за 990 по своей базе).** Сначала продавать №1 шире (эксперты + твёрдый бизнес), №2 наращивать осторожно.
