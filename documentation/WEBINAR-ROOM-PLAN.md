# WEBINAR-ROOM-PLAN.md — Вебинарная комната (стрим + чат + продажи + аналитика)

> Статус: **план / проектирование** (2026-07-16). Код ещё не пишется.
> Идея: своя вебинарная комната на pluson.ru — как в GetCourse (тип трансляции «Видеокодер»),
> но встроенная в ПЛЮСОН: **на каждый день события**, с чатом, продающими блоками,
> реакциями по спикерам, батлами, опросами и аналитикой присутствия «сколько людей по часам».
> Референс, который дал владелец: вебинарная комната GetCourse (RTMP-видеокодер + аналитика зрителей по времени).

---

## Суть в одном абзаце

Zoom (или OBS поверх Zoom) вещает **видеопоток по RTMP** через видеокодер на наш media-сервер
**MediaMTX**, который раздаёт его зрителям как **HLS**. Зритель открывает страницу
`pluson.ru/webinar/{slug}/{day}` и в одном окне видит: видео, живой чат, продающие блоки
(кнопки и формы заявок), реакции на спикеров (👍/👎), опросы, батлы. Всё, что он делает,
пишется с его `contact_id` → строится аналитика «сколько уникальных было и сколько по часам»
+ активность каждого зрителя (для будущих игровых механик).

⚠️ **Почему не «просто ссылка на Zoom».** Zoom нельзя встроить в браузерный `<iframe>` —
его SDK это запрещает. Вебинарная комната ≠ ссылка на созвон. Комната = **страница на нашем
домене со встроенным плеером**, рядом с которым чат и продажи, а человек **не уходит** со страницы.

## Что решено (зафиксировано владельцем)

| Вопрос | Решение |
|---|---|
| Media-сервер | Свой **MediaMTX** (RTMP→HLS), проще в настройке, всё на pluson.ru |
| Гейт по тарифу | **Экстра (vip)** — своя комната; **Профи (pro)** — только ссылка на стороннюю комнату |
| Привязка комнаты | На **каждый ДЕНЬ** события со слотами (к `conf_days`), не одна на событие |
| Навигация по дням | Вкладки/селектор дней, **как программа конференции** (`ProgramTab`) / этапы турнира |
| Продающие блоки | Настраиваемые «как в GetCourse»: кнопки + умные формы заявок |
| «Группы» (GetCourse) | Через теги контактов — заполнил форму → контакт + **тег формы** |
| Реакции | Везде **👍/👎 с редактируемыми названиями** («вода/мясо»), привязка к спикеру. **👎 — настраиваемая** (тумблер «показывать отрицательную или только положительную»). Рядом с пальцами — счётчик |
| Батлы | **Делаем сразу**, отдельной фичей; спикеры **выбираются из события** |
| Подарки спикера | Всплывают **по таймингу программы** (привязка к слоту) |
| Опросы/голосования | Есть, отдельно от форм заявок |
| Активность зрителя | Считается **по каждому зрителю** (сообщения + реакции) — фундамент под геймификацию |
| Форма входа | Не зареган на событие → форма контактов (все поля); зареган → пускаем без ввода |
| Удаление участника | Есть — бан/удаление из эфира и чата |
| Кнопка «Подписаться на спикера» | Авто-смена по слоту + плашка «Сейчас выступает: {имя}» |
| Редирект после эфира | Настраиваемая ссылка «куда перебросить после завершения» |

## 1. Как устроен поток и путь зрителя

```
┌─────────────┐   RTMP    ┌──────────────────┐   HLS    ┌────────────────────┐
│  Zoom / OBS │ ────────► │  MediaMTX (наш)  │ ───────► │  Комната дня       │
│ видеокодер  │  ключ     │ rtmp://…/live/KEY │  .m3u8   │ плеер+чат+блоки    │
└─────────────┘           └──────────────────┘          └────────────────────┘
```

1. Клиент в дашборде у **дня** события включает тип трансляции «Видеокодер».
2. Мы показываем ему **RTMP-адрес** `rtmp://pluson.ru/live/{stream_key}` + **ключ**.
3. Он вставляет их в Zoom (Custom Live Streaming, Zoom Pro+) или в OBS.
4. Поток идёт на MediaMTX → раздаётся как HLS (`hls.js` в браузере).
5. Зритель открывает комнату дня и видит эфир + всю интерактивную обвязку.

**Профи (pro):** вместо видеокодера — поле «Ссылка на стороннюю комнату», кнопка «Смотреть»
ведёт наружу. Ни чата, ни блоков, ни аналитики внутри комнаты нет (это чужая платформа).

## 2. Что видит зритель — комната дня `pluson.ru/webinar/{slug}/{day}`

Одна страница, ничего не открывается в новых вкладках. Работает в вебе и в Telegram Mini App.

- **HLS-плеер** — автоподбор качества (высокое/среднее/низкое), «Трансляция скоро начнётся»
  до старта, «Трансляция завершена» → редирект на заданную ссылку. Звук, полный экран.
- **Живой чат** (WebSocket) — сообщения в реальном времени. Модерация: премодерация,
  «видно только модератору», удаление/бан участника, отключение чата. Имя из контакта/платформы.
- **Продающие блоки** (настраиваемые, любые продукты):
  - `button` — кнопка «название + ссылка»;
  - `form` — **умная форма заявки** (см. ниже);
  - `speaker_follow` — авто-кнопка «Подписаться на спикера» + плашка «Сейчас выступает: {имя}»;
  - `gift` — подарок спикера, всплывает по таймингу его слота.
  - У каждого блока — тайминг `show_at_min / hide_at_min` (появиться на N-й минуте).
- **Реакции 👍/👎 по спикерам** — названия реакций редактируются («вода/мясо»). Счётчик
  можно вывести на каждого спикера. Живое обновление через WS.
- **Опросы/голосования** — ведущий запускает («Какая тема ближе?», варианты A/B/C),
  зрители тыкают, результаты видны в реальном времени.
- **Батлы** — отдельная фича, спикеры выбираются из события, под каждым 👍/👎 (см. раздел 6).

### Умная форма заявки и вход

- **Известный контакт** (зашёл с `contact_id` — из бота/Mini App/по своей ссылке):
  форма без полей — одна кнопка **«Оставить заявку»** в один тап. Не заставляем вводить то,
  что уже знаем.
- **Неизвестный** (нет `contact_id`): форма ввода **всех контактов** (имя, телефон, email,
  ник) → создаём/обновляем контакт.
- **Вход в комнату:** не зареган на событие → предлагаем регистрацию (форма контактов);
  зареган → пускаем сразу без ввода.
- Итог заполнения формы: контакт получает **тег этой формы** = «группа» GetCourse.
  Потом фильтр по тегу в Контактах / рассылка. Отдельную сущность «Группы» **не плодим** —
  переиспользуем существующую систему тегов.

## 3. Аналитика — «сколько людей по часам» + активность каждого

Отдельный движок. Пока зритель на странице с играющим плеером и вкладка в фокусе — раз в
минуту летит **heartbeat**. Из сигналов строится линия «Уникальные онлайн по времени», поверх —
точки активности.

**Метрики (плитки):** всего уникальных, пик онлайн (и во сколько), вовлечённость,
комментариев, кликов, заказов/оплат.

**График:** линия «уникальные онлайн», разбивка **5 / 10 / 20 / 40 / 60 мин**, зум по времени,
наложение кликов/комментов/заказов/оплат с таймкодом эфира. Фильтр по устройству (desktop/mobile).

**Срез аудитории:** «кто был онлайн 14:00–14:30» → список контактов → тег/сегмент/рассылка
(аналог кнопки «Перейти к выбранному сегменту зрителей» в GetCourse).

**⚠️ Активность ПО КАЖДОМУ ЗРИТЕЛЮ** (ключевое требование под геймификацию): по каждому
контакту считаем — сколько сообщений написал, сколько реакций (👍/👎) поставил, каким спикерам.
Вся активность пишется с `contact_id`, агрегируется по зрителю → в будущем игровые механики
на активность (баллы за активность, топ зрителей и т.п.).

## 4. Тарифный гейт и media-сервер

- Гейт **по фиче, не по slug** (как остальные модули проекта):
  - `webinar_room` — своя комната (Экстра / vip).
  - `webinar_link` — ссылка на стороннюю (Профи+ / pro).
- **MediaMTX** — отдельный процесс на проде, как `wa-bridge`: основной стек
  (api/celery/bot/web) не задевает. systemd-юнит, RTMP-вход по ключу, HLS-выход через nginx.
- ⚠️ Нагрузка: живой эфир = CPU/трафик. Нужен мониторинг во время событий. Не запускать
  тяжёлые операции с media-сервером во время живого события (правило проекта).

## 5. Реакции 👍/👎 и подписка на спикера

- Везде две реакции на спикера, **названия редактируются клиентом** (дефолт 👍/👎, можно
  «вода/мясо», «плохо/хорошо»).
- **Отрицательная реакция настраивается** — тумблер «показывать 👎 или только 👍».
  Выключено → зрителю видна только положительная реакция; включено → обе.
- **Счётчик рядом с каждой реакцией** — сколько собрано (живой, через WS).
- Реакция **всегда привязана к спикеру** — общего «эфира без спикера» нет: всегда кто-то
  ведёт (минимум организатор, его тоже можно добавить как «спикера дня»).
- Счётчик реакций по каждому спикеру — живой (WS).
- **«Подписаться на спикера»** (`speaker_follow`): плашка «Сейчас выступает: {имя}» + кнопка
  подписки на его канал. Оба **сами сменяются по таймингу слота программы дня** (кто сейчас
  в эфире по `conf_sessions` — того имя и канал). Каналы берём из карточки спикера
  (`tg_channel_url` / `vk_url` / `max_url`).
- **Подарок спикера** — всплывает по таймингу его слота. Источник — существующие поля
  `event_collaborators.gift_after_speech_*` или привязанный лид-магнит/пакет.

## 6. Батлы (отдельная фича, делаем сразу)

- Спикеры **выбираются из события** (не ввод имён руками) — из `event_collaborators`.
- На каждого спикера в батле — **две реакции 👍/👎 с редактируемыми названиями** (счётчики).
- Ведущий запускает батл в эфире → зрители жмут → у каждого спикера копятся оценки.
- Статусы батла: готовится / идёт / завершён.
- Заложено под будущее **отдельное событие «Батлы»** (может стать отдельным `module_slug`),
  но в первой версии — блок внутри вебинарной комнаты.

## 7. Таблицы БД (новые миграции)

Комната привязана к **дню** события (`conf_days`). Ничего из текущей схемы не ломаем.

### webinar_rooms — комната на день
```
id, event_id, day_id (FK conf_days), title (правится, fallback «День N»), starts_at,
stream_type (encoder | external_link), stream_key, hls_url, external_url, status (idle|live|ended),
hide_viewer_count BOOL, chat_enabled BOOL, premoderation BOOL, redirect_url,
reaction_up_label, reaction_down_label, show_down_reaction BOOL DEFAULT TRUE,  -- реакции спикерам: названия + показывать ли 👎
started_at, ended_at, created_at, updated_at
```
UNIQUE(day_id) — одна комната на день.

### webinar_presence — присутствие (heartbeat)
```
id, room_id, contact_id, bucket_at (минута, округлённая), device (desktop|mobile)
```
UNIQUE(room_id, contact_id, bucket_at) → одна точка в минуту → уникальные онлайн.

### webinar_chat_messages — чат
```
id, room_id, contact_id, text, at, status (visible|hidden|premod)
```
Бан/удаление участника — статус тут + отметка в presence.

### webinar_blocks — продающие блоки
```
id, room_id, kind (button | form | speaker_follow | gift),
title, url,                         -- для button
form_fields JSONB, form_tag,        -- для form (какие поля + тег-«группа»)
follow_mode (auto | fixed), speaker_id,  -- для speaker_follow / gift
show_at_min, hide_at_min, sort_order, is_active
```

### webinar_activity — единый поток активности (по зрителю)
```
id, room_id, contact_id, at, kind (click | form_submit | order | payment | reaction | poll_vote | chat_msg),
target_kind (block | speaker | poll_option | battle_player), target_id, value
```
Основной источник аналитики по зрителю (сколько сообщений/реакций у каждого).

### webinar_speaker_reactions — счётчики реакций спикерам
```
id, room_id, speaker_id (event_collaborators.id), reaction_key (up|down), label, count
```
`label` — редактируемое название реакции. Денормализованный счётчик для быстрого показа (WS).

### webinar_polls / webinar_poll_options — опросы
```
polls:   id, room_id, question, status (open|closed), created_at
options: id, poll_id, text, votes
```

### webinar_battles / webinar_battle_players — батлы
```
battles: id, room_id, title, status (draft|live|ended), reaction_up_label, reaction_down_label, show_down_reaction BOOL
players: id, battle_id, speaker_id (event_collaborators.id), up_count, down_count, sort_order
```

### webinar_registrations — запись тех, кого нет в базе
```
id, room_id, contact_id, created_at
```
Создаём контакт при регистрации на странице входа + вешаем тег комнаты/дня.
Известные контакты сюда не идут (заходят сразу).

## 8. API и реалтайм

### Публичные (страница зрителя)
```
GET  /public/webinar/{slug}/{day}              — данные комнаты дня: плеер, статус, чат, блоки, спикеры
WS   /ws/webinar/{slug}/{day}                  — чат, presence, блоки, реакции, батлы, опросы (realtime)
POST /public/webinar/{slug}/{day}/heartbeat    — пинг присутствия раз в минуту (fallback без WS)
POST /public/webinar/{slug}/{day}/chat         — отправить сообщение
POST /public/webinar/{slug}/{day}/form/{block} — умная форма: заявка (известный) / регистрация (новый) → контакт + тег
POST /public/webinar/{slug}/{day}/react        — 👍/👎 спикеру / игроку батла
POST /public/webinar/{slug}/{day}/poll/{id}/vote — голос в опросе
POST /public/webinar/{slug}/{day}/track        — клик по кнопке / заказ / оплата
POST /public/webinar/{slug}/{day}/register     — страница записи для тех, кого нет в базе
```

### Клиентские (дашборд + аналитика)
```
GET  /events/{id}/webinar/{day}/analytics          — всего уникальных + график по интервалам 5/10/…/60 + активность зрителей
POST /events/{id}/webinar/{day}/segment            — срез: онлайн в интервале → тег/сегмент контактов
POST /events/{id}/webinar/{day}/chat/{id}/moderate — скрыть / премодерация сообщения
POST /events/{id}/webinar/{day}/participant/{id}/remove — удалить/забанить участника из эфира и чата
POST /events/{id}/webinar/{day}/battle             — создать/запустить батл (выбор спикеров)
POST /events/{id}/webinar/{day}/poll               — запустить опрос
CRUD /events/{id}/webinar/{day}/blocks             — продающие блоки дня
GET/PATCH /events/{id}/webinar/{day}               — настройки комнаты дня
```

## 9. Интерфейс — вкладка «Вебинары»

Новая вкладка события «Вебинары». Внутри — навигация по дням **вкладками/селектором дня,
как программа конференции** (или этапы турнира). Выбрал день → его комната.

- **Дни вкладками** — переключатель дней вверху (как `ProgramTab` / этапы турнира).
  Каждый день = своя комната. Название дня правится, дата рядом.
- **Настройки комнаты дня** — тип трансляции (Экстра: видеокодер / Профи: ссылка),
  RTMP-адрес+ключ, тумблер «скрывать число зрителей», чат вкл/премодерация,
  ссылка редиректа после эфира.
- **Конструктор блоков** — список продающих блоков дня: кнопки, формы (с тегом),
  авто-кнопка спикера, подарок; тайминг показа. Добавить/править/удалить.
- **Пульт ведущего (в эфире)** — запуск блоков/опросов/батлов; выбор спикеров в батл;
  счётчики реакций по спикерам; модерация чата и удаление участников — на живой странице.

## 10. Этапы разработки

| # | Этап | Содержание | Оценка |
|---|---|---|---|
| 1 | Media-сервер | MediaMTX на прод (отдельный процесс, systemd, nginx). RTMP-вход по ключу → HLS. Тест: OBS/Zoom → поток → HLS играет | ~1 день |
| 2 | Комната + плеер + настройки | Страница `/webinar/{slug}/{day}` с hls.js. Вкладка «Вебинары»: дни, тип трансляции, ключ, редирект, скрытие счётчика | ~2–3 дня |
| 3 | Чат + модерация + удаление участника | WS-чат, премодерация, бан/удаление | ~2 дня |
| 4 | Продающие блоки + умные формы + теги | Конструктор блоков, кнопки/формы, авто-кнопка спикера, подарок по таймингу, страница регистрации | ~2–3 дня |
| 5 | Реакции 👍/👎 + подписка на спикера | Реакции по спикерам (редактируемые названия), плашка «Сейчас выступает», авто-смена по слоту | ~1–2 дня |
| 6 | Опросы + батлы | Голосования в эфире; батлы с выбором спикеров и 👍/👎 | ~2–3 дня |
| 7 | Аналитика | Heartbeat, агрегация по бакетам, дашборд-график 5/10/…/60, активность по зрителю, срез в сегмент | ~2–3 дня |

Порядок можно менять; п.1 и п.2 — фундамент, остальное наращивается на комнату.

## 11. Открытые вопросы (перед стартом кода)

1. **Регистрация неизвестных** — уточнено: собираем **все контакты** (имя, телефон, email, ник).
2. **MediaMTX на проде** — согласовать окно установки (не во время живого события).
3. **Гейт-фичи** — завести `webinar_room` (Экстра) и `webinar_link` (Профи+) в `features`
   + привязать к тарифам (зеркалить в trial, т.к. trial = pro по фичам).
