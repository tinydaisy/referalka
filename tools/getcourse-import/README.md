# Импорт уроков и курсов из GetCourse

Инструмент разовой миграции: выгружает тренинги и уроки из аккаунта GetCourse
в JSON, готовый к заливке в модуль «Продукты» ПЛЮСОНа (миграции 290–294).

## Зачем это скриптом, а не через API

**У GetCourse нет публичного API для контента.** Их официальное API
(`/pl/api/account/...`) отдаёт только пользователей, заказы и сделки — уроков,
тренингов и текстов там нет вообще. Поэтому читаем так же, как это делает
браузер: логинимся формой админки и разбираем страницы.

## Как пользоваться

```bash
cd tools/getcourse-import

export GC_BASE=https://ваш-аккаунт.getcourse.ru
export GC_LOGIN=you@example.com
export GC_PASSWORD='пароль'

python3 export_getcourse.py                        # все тренинги
python3 export_getcourse.py --training 934770323   # один тренинг
python3 export_getcourse.py --download             # + скачать картинки и файлы
python3 export_getcourse.py --keep-header-image    # оставить баннер-шапку
```

Результат — `export.json`. Реквизиты только в переменных окружения, в коде их
нет. Cookies кешируются в `cookies.pkl`, чтобы не логиниться каждый раз
(файл в `.gitignore`).

## Формат выгрузки

Типы блоков совпадают с `material_blocks.kind` (миграция 294), поэтому заливка
в базу — прямой перенос, без второго преобразования.

```json
[{
  "gc_id": 934770323,
  "title": "БОНУС «Продажи по версии Форбс»",
  "lessons": [{
    "gc_id": 344244153,
    "title": "Как обрести внутренний статус",
    "header_image": "https://fs-thb01.getcourse.ru/…",
    "blocks": [
      {"kind": "text",  "body": "<p>Добрейшего-богатейшего!</p>…"},
      {"kind": "video", "url": "https://www.youtube.com/watch?v=oL8DQbo69LM"}
    ]
  }]
}]
```

## Баннер-шапка выносится из содержимого

⚠️ Картинка **первым блоком** урока — это баннер тренинга, а не содержимое.
В выгружаемом аккаунте на 44 картинки пришлось **5 уникальных файлов, и все
стояли позицией 0**: одна шапка на тренинг, повторяющаяся в каждом его уроке.
Содержательных картинок внутри уроков не оказалось ни одной.

Такая шапка не попадает в `blocks`, а уходит в поле `header_image` урока —
ссылка не теряется и может пригодиться обложкой продукта. Вернуть её в
содержимое — ключ `--keep-header-image`.

## Что важно знать про содержимое

**Видео не скачиваются — и не должны.** В блоке хранится ссылка на
YouTube/Rutube/VK, ровно как задумано в ПЛЮСОНе («своё видео не храним»,
миграция 294). Закрытие аккаунта GetCourse их не затрагивает.

## Перезаливка картинок в R2

Аккаунт GetCourse закрывается — ссылки на `fs.getcourse.ru` однажды умрут.
Второй скрипт переносит всё к нам и подменяет ссылки прямо в `export.json`:

```bash
export CF_ACCOUNT_ID=… CF_R2_ACCESS_KEY_ID=… CF_R2_SECRET_ACCESS_KEY=…
export CF_R2_BUCKET_NAME=referalka CF_R2_PUBLIC_URL=…

python3 tools/getcourse-import/migrate_media_to_r2.py --client-id 1 --dry-run
python3 tools/getcourse-import/migrate_media_to_r2.py --client-id 1
```

⚠️ **Дедуп по СОДЕРЖИМОМУ (SHA-256 байтов), а не по адресу.** Баннер лежит в
каждом уроке тренинга: 44 ссылки свелись к **2 файлам**. Сверять по строке
адреса нельзя — у GetCourse один файл раздаётся по разным URL (разные
параметры превью), и дубли бы прошли мимо.

⚠️ Скрипт **не импортирует** `app.services.r2_storage`: тот тянет `app.config`
→ `pydantic_settings` и остальной стек бэкенда, которого на машине
разработчика может не быть. Ключ строится тем же правилом, что
`build_key(kind='material_media')` → `clients/{id}/materials/media/{uuid}.{ext}`.

## Три грабли, на которых ломается наивная реализация

**1. Формы `<form>` на странице входа нет** — она рисуется JavaScript'ом.
Логин идёт POST-ом multipart на `/pl/api/user/auth/login` (контракт подсмотрен
в бандле `/nassets/*/index.js`).

**2. Запрос подписан.** Нужны `requestTime` + `requestSimpleSign` со страницы
входа — они лежат в JSON внутри HTML под ключом `authPageInfo`.

**3. Нужны 4 значения счётчика** — `gcSession`, `gcVisit`, `gcVisitor`,
`gcSessionHash`. В браузере их кладёт в `localStorage` скрипт
`/public/js/gccounter-new.js`, дёргая `/stat/counter`, а тот отдаёт готовый JS
с `localStorage.setItem`. Без них сервер отвечает «Ошибка валидации входных
данных» — и это единственное, что он сообщает.

## ⚠️ Модуль в GetCourse — это ВЛОЖЕННЫЙ ТРЕНИНГ

Группировка уроков есть, но выглядит она не так, как ожидаешь: **модуль — это
такой же тренинг, вложенный в родительский**. Отдельной сущности «модуль» или
«раздел» в их модели нет.

⚠️ Раздел «Тренинги» (`/teach/control`) отдаёт **только верхний уровень**, и в
его JSON у всех записей `parentId = null` — выглядит как полный плоский список.
Родительские тренинги при этом кажутся пустыми («уроков: 0»), хотя весь их
контент лежит во вложенных модулях.

Цена ошибки на этом аккаунте:

| | По плоскому списку | По дереву |
|---|---|---|
| Узлов | 12 | **40** |
| Уроков | 47 | **173** |

То есть наивная выгрузка теряет **две трети содержимого**, и выглядит при этом
совершенно успешной.

Вложенность живёт только в разметке `/teach/control/stream/tree`: `<li
data-id="…">` с вложенными `<ol class="dd-list level-N">`. JSON там нет вовсе —
разбирается HTML (`training_tree()`). Глубина любая; в выгрузке она
сохраняется полями `level` и `parent_gc_id`, и ложится на
`product_sections` (миграция 291 — вложенность любой глубины).

## Два движка уроков — обе ветки обязательны

⚠️ В одном аккаунте уживаются **два формата уроков**, и выглядят они снаружи
одинаково:

| Движок | Где содержимое | Разбирает |
|---|---|---|
| Новый | JSON в HTML под ключом `"blocks"` | `parse_blocks()` |
| Старый | готовая разметка `<div class="… lt-lesson-text …">`, JSON нет вовсе | `parse_blocks_html()` |

Поддержать только новый — значит молча получить пустые уроки: в этом аккаунте
таких было **7 из 47**, и по логу выгрузки они выглядели как «урок без
содержимого», а не как ошибка. **При доработке проверять оба формата.**

## Что вычищается при выгрузке

- **Инлайновые стили и классы GetCourse** — тянут их шрифты, отступы и цвета,
  в нашем редакторе выглядят чужеродно. Разметка (абзацы, списки, жирный,
  ссылки) остаётся.
- **`<script>` и `<style>`** — в старом формате разметка блока идёт вперемешку
  с JS живого обновления (websocket-подписки), и без вырезания он попадает
  прямо в текст урока.
- **Текст-рыба GetCourse** («Сущность и концепция маркетинговой программы…») —
  ею заполняется только что созданный блок, клиент её не писал.
- **Превью вместо оригинала картинки.** `<img src>` ведёт на уменьшенную копию
  (`/s/f1200x/`). ⚠️ Собрать прямую ссылку на оригинал
  (`/file/download/a/<хеш>`) **нельзя** — она отвечает 500: у файлового сервиса
  свои параметры аккаунта, и в адресе превью они уже есть. Поэтому ссылка не
  ломается, а лишь поднимается ширина до `f9999x` — сервис отдаёт оригинал,
  если запрошенный размер больше исходного (проверено: 223 КБ → 472 КБ).

## ⚠️ Ссылки на файлы берутся из HTML, а не собираются из JSON

В `params.image` блока лежит `{hash, fileName}`, и напрашивается собрать адрес
из хеша. **Так нельзя:** хеш в JSON ДРУГОЙ, чем в рабочей ссылке (`87e8…` в
JSON против `dee3…` в HTML), а сам адрес требует номера аккаунта и параметра
`sc`:

```
/fileservice/file/download/a/904149/sc/141/h/<хеш>.png
```

Наивно склеенный `/download/a/<хеш>` отвечает 500. На этом тихо ломалась
перезаливка — **37 файлов из 44 не скачались**, а выгрузка при этом выглядела
успешной. Поэтому адреса вычитываются из самой страницы урока по порядку
появления (`_FS_URL_RE`).

## Результат миграции (2026-08-14)

Аккаунт `ivision-medialift.getcourse.ru`: **40 узлов (12 продуктов +
28 разделов), 173 урока, 479 блоков** — 295 текстовых, 178 видео
(138 YouTube + 40 Rutube), 4 кнопки, 2 картинки. Пустых уроков нет.

Ещё 156 баннеров-шапок вынесены в `header_image` и в содержимое не идут.
Картинки перезалиты в R2 кабинета 1: **158 ссылок → 2 файла** (логотип
iVISION 245×320 и брендовая шапка 2032×505), 0,5 МБ. Ссылок на `getcourse.ru`
в выгрузке не осталось — аккаунт можно закрывать.

Тренинги переносятся **как есть, один в один** — по решению владельца
объединять похожие («Крео СПРИНТ» и «Спринт по упаковке» дублируют друг друга)
не нужно.
